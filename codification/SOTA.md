## 3. Selector specs for Aryan (post-hoc, one candidate at a time, no other model's answers, no gold)

**S-1. BMC best-of-N** (2604.16565 §3, implementation details "BMC uses masking ratio γ = 0.9 and K = 16").
For each of the item's N candidates $y$ (cut after `#### N`, I-22): re-mask each answer token independently
with probability 0.9; reconstruct with the **same** DLM for K = 16 denoising steps, prompt unchanged; score
$s(y) = \cos(\phi(y), \phi(\hat y))$ with $\phi$ = `sentence-transformers/all-MiniLM-L6-v2` mean embedding. Pick
the argmax; ties go to the earliest index. Needs GPU: 16 forward passes per candidate. The paper also mixes in
an intrinsic-confidence term whose weight I did not extract, so this spec is the **semantic-only variant**
[deviation, stated]. Run on dev and gate only, against tuned majority.

**S-2. S³ composite verifier as a vote weight, CPU-only** (2604.06260 App. C.1–C.3, Table 3 GSM8K row
α = (0.20, 0.25, 0.25, 0.10, 0.20, 0)). Per candidate, compute s1 structural completeness, s2 internal arithmetic
consistency, s3 answer reachability and s5 non-degeneracy exactly as App. C.3 defines them. **Drop s4 (model
confidence)**: it needs DLM probabilities that are not cached. Renormalise the remaining weights to sum to 1.
Use $f(y)$ as the weight in a weighted majority vote over extracted answers; ties go to the earliest index; all
answers None gives index 0. This is close to our iteration-1 merged rule 4.1 (arithmetic-verification-weighted
voting), so expect a small effect. It is cheap to test in a copy of `baselines.py`.

## 4. Novelty of idea 1.1

- **"An external scorer reranks DLM candidates" is not novel.** 2609.35472 (trained ORM, +15.1 pp over majority
  on Dream-Instruct) and 2604.16565 (training-free BMC) both do it. Neither uses a small frozen **AR** LM's
  likelihood. HEX reports that likelihood tie-breaking adds nothing.
- **"AR-representation preservation matters" is now partly occupied.** 2605.06885 (May 2026) argues
  "representation preservation [is] a missing ingredient in AR → DLM conversion" and enforces it with layer-wise
  cosine alignment. It links preservation to **training efficiency and code quality**, not to test-time
  selection.
- **"Preservation (CKA to the AR base) predicts how much AR reranking recovers": no prior work found** in the
  full texts above or in the search (0 CKA hits). This remains the defensible novel claim, with the caveats
  already on record: n = 4 adapted models, three of them at the floor, and I-22. The paper should cite 2605.06885
  as the closest related idea and say what differs.
- Limits: arXiv only (the Semantic Scholar API was not tried); one day; the abstract-field search can miss papers
  that use other wording.
