4. **Trajectory‑Entropy‑Guided Compute Allocation for Diffusion Language Models**  

1. **Model & Backbone Preparation**  
   - Select three publicly released DLMs that span the two families:  
     *DiffuGPT‑S* (127 M, GPT‑2‑based), *DiffuLLaMA* (6.74 B, LLaMA‑based), and *Dream‑7B* (7 B, LLaMA‑based).  
   - For each DLM retrieve its autoregressive backbone (GPT‑2‑small for DiffuGPT‑S; LLaMA‑2‑7B for the two 7B models). No fine‑tuning or continual‑pre‑training is performed – the study is strictly inference‑only.  

2. **Representation‑Preservation Baseline (Control)**  
   - On the WikiText‑103 validation split (≈ 5 k sentences) run each DLM and its AR backbone in fp16 with activation‑checkpointing.  
   - For every transformer layer compute **Centered Kernel Alignment (CKA)** between the DLM hidden‑states and the frozen AR hidden‑states.  
   - Average CKA across layers to obtain a single **Representation‑Preservation Score (RPS)** per model.  
   - (Optional) Validate RPS with a lightweight linear‑probe next‑token task on a small held‑out set to confirm that the score correlates with functional AR knowledge.  

3. **Denoising‑Trajectory Entropy Measurement (Novel Proxy)**  
   - For each DLM, sample a **representative prompt subset** (50 prompts, stratified across HumanEval, GSM8K, SIQA/WinoGrande).  
   - At each denoising timestep *t* = 1…*T* (where *T* = 256, the maximum step budget we will test) do:  
     a. Run the DLM’s diffusion sampler *up to* step *t* starting from pure noise, obtaining the partially denoised token sequence \(\hat{x}_{0}^{(t)}\).  
     b. Perform a **teacher‑forcing forward pass** of the DLM on \(\hat{x}_{0}^{(t)}\) (no gradient) to get the logits for the next‑token distribution at every position.  
     c. Compute the **Shannon entropy** of the token distribution at each position, then average over all positions and over the 50 prompts → \(H_t\).  
   - This yields an **entropy trajectory** \(\{H_1, H_2, …, H_T\}\) that quantifies the model’s predictive uncertainty as denoising proceeds.  
   - Derive two scalar summary metrics from the trajectory:  
     * **Entropy‑Area‑Under‑Curve (EAUC)** = \(\frac{1}{T}\sum_{t=1}^{T} H_t\) (lower EAUC → faster convergence to a low‑entropy, AR‑like regime).  
     * **Half‑Entropy Step (HES)** = the smallest *t* such that \(H_t \le 0.5 \cdot H_1\) (the step at which uncertainty has dropped to half its initial value).  
   - Both EAUC and HES are computed in fp16; the extra forward passes add roughly the same cost as one extra generation pass per prompt (≈ 2 GPU‑hrs total for all three models).  

4. **Prompt Pool & Batch Construction**  
   - Build a **stratified prompt set** of 300 instances (100 each from HumanEval, GSM8K, SIQA/WinoGrande).  
   - Within each dataset split the prompts into three difficulty tiers (easy/medium/hard) based on the AR backbone’s baseline performance (pass@1 for HumanEval, exact‑match for GSM8K, accuracy for SIQA/WinoGrande).  
   - For each tier create balanced mini‑batches of size = 4 (mixed domains) to maximise GPU utilisation while keeping variance low.  

5. **Candidate Generation Across Compute Budgets**  
   - For every DLM and every prompt in the full 300‑prompt pool:  
     - Run the native diffusion sampler at three denoising‑step budgets: **Low = 16**, **Medium = 64**, **High = 256** steps.  
     - At each budget generate **N ∈ {1, 2, 4, 8}** independent samples (different seeds).  
     - Use fp16 + activation‑checkpointing; for DiffuLLaMA additionally test 4‑bit quantisation *only* for the generation phase (the entropy and RPS calculations stay in full precision).  
     - Store the generated token sequences (as IDs) to avoid recomputation for scoring.  

6. **Lightweight AR Reranking**  
   - Load a tiny AR scorer (GPT‑2‑small, 124 M) in fp16.  
   - For each set of N candidates compute the **average negative log‑likelihood (NLL)** of the full sequence (including EOS).  
   - Choose the candidate with the lowest NLL as the “sampling + reranking” output.  
   - The scorer runs on a single CPU core; its latency is overlapped with GPU kernel launches via CUDA streams, making its overhead negligible for the efficiency metric.  

7. **Quality Evaluation**  
   - For every output (denoising‑only and sampling + reranking) compute three task‑specific scores:  
     • HumanEval pass@1 and pass@10 → averaged → **code score**.  
     • GSM8K exact‑match accuracy.  
     • SIQA/WinoGrande accuracy (averaged).  
   - Normalise each raw score to \([0,1]\) across **all** conditions (model × step × N × strategy).  
   - Take the unweighted mean of the three normalised scores → **Quality** ∈ \([0,1]\).  

8. **Efficiency Measurement & QET**  
   - Measure **wall‑clock latency per generated token** (including scorer overhead for the reranking condition) using `torch.cuda.Event` timestamps, averaged over all prompts and repetitions.  
   - Convert latency to **Estimated Compute**:  \(\text{EstCompute} = \text{latency\_per\_token} \times \text{peak\_FP16\_throughput} \) (≈ 140 TFLOPs for the RTX 6000 Pro Blackwell).  
   - Define **Quality‑Efficiency Trade‑off (QET) = Quality / EstCompute**. Higher QET → more quality per unit of compute.  

9. **Analysis Pipeline**  

   a. **Marginal QET Gains**  
      - ΔQET_denoise = QET(high steps, N=1) − QET(low steps, N=1) (and low→medium, medium→high).  
      - ΔQET_sample = QET(medium steps, N=8) − QET(medium steps, N=1) (and 1→4, 4→8).  

   b. **Predictive Power of Representation vs. Trajectory Entropy**  
      - For each model compute the three predictors: RPS (from Step 2), EAUC, and HES (from Step 3).  
      - Using the six models (three DLMs × two families) compute **Spearman’s ρ** between each predictor and the two sets of marginal gains (ΔQET_denoise, ΔQET_sample).  
      - To test whether trajectory entropy adds predictive value beyond RPS, fit a **hierarchical linear model**:  
        \[
        \Delta QET = \beta_0 + \beta_1 \text{RPS} + \beta_2 \text{EAUC} + \beta_3 \text{Family} + \epsilon
        \]  
        (and an analogous model with HES). Compare adjusted R² and perform a likelihood‑ratio test to see if EAUC/HES significantly improves fit.  

   c. **Interaction Analysis**  
      - Fit a **linear mixed‑effects model** with QET as the outcome:  
        \[
        \text{QET} \sim \text{RPS} \times \text{StepBudget} \times N + \text{EAUC} \times \text{StepBudget} \times N + (1|\text{Model}) + (1|\text{PromptDifficulty})
        \]  
        - Test whether the slope of EAUC (or HES) differs across step budgets and N, and whether the interaction differs between GPT‑2‑ and LLaMA‑based families (include Family as a fixed effect).  

   d. **Bootstrap Uncertainty**  
      - Resample the 300 prompts (with replacement) 1 000 times, recompute RPS, EAUC/HES, QET, marginal gains, and all correlation/regression coefficients.  
      - Report 95 % confidence intervals for each metric.  

   e. **Decision‑Rule Exploration (Optional, for Practical Guidance)**  
      - Derive a simple threshold policy: if **EAUC < τ₁** (i.e., the model’s entropy drops quickly) *or* **RPS > τ₂** (strong AR representation) then allocate extra compute to **sampling + reranking**; otherwise allocate to **more denoising steps**.  
      - Optimise τ₁ and τ₂ on a held‑out 20 % of the prompt set via grid search and report the resulting QET improvement over a uniform‑step baseline.  

10. **Validation & Robustness Checks**  
    - **Ablation of entropy metric**: repeat Steps 3‑9 using **per‑token variance** or **maximum probability (confidence)** instead of Shannon entropy to ensure conclusions are not entropy‑specific.  
    - **Quantisation sanity check**: compare QET curves for full‑precision vs. 4‑bit DiffuLLaMA to confirm that quantisation does not invert the observed trend.  
    - **Alternative scorer**: repeat reranking with a 30 M‑parameter distilled GPT‑2 to verify that scorer size does not drive the EAUC/HES‑QET relationship.

Research problem: Does the extent to which a diffusion language model (DLM) preserves the autoregressive (AR) representations of its pretrained backbone determine whether allocating additional inference compute to (a) more denoising steps or (b) generating more candidates and reranking them with a tiny AR scorer yields a larger improvement in the quality‑efficiency trade‑off, and does this relationship vary across model families (GPT‑2‑based vs. LLaMA‑based) and denoising‑step budgets?
Rationale: The target paper demonstrates that continual‑pre‑training of open‑source AR models yields competitive DLMs (DiffuGPT, DiffuLLaMA) but leaves a measurable “accuracy headroom” (L6) that could be closed either by running more denoising steps or by better exploiting the model’s inherent candidate diversity. Recent inference‑time methods such as Jacobi Forcing (self‑distillation of parallel decoding trajectories) and TESS 2’s reward guidance show that quality can be traded for efficiency, yet it remains unclear *which* compute allocation—more denoising versus more sampling with lightweight reranking—is more effective for a given DLM, and whether this depends on how much AR knowledge the model retains after adaptation.  

If a DLM closely preserves the AR backbone’s representations, its internal denoising process may already be well‑aligned with the AR prior, suggesting that additional denoising steps yield diminishing returns while sampling more candidates and reranking with a lightweight AR model could recover the headroom more efficiently. Conversely, if representation preservation is low, extra denoising may be needed to compensate for misaligned representations. By quantifying representation preservation and systematically measuring the quality‑efficiency outcomes of the two compute‑allocation strategies across multiple released DLMs, we can test this hypothesis and provide practitioners with a principled rule for allocating inference budget between denoising and selection when deploying scaled diffusion language models.

**Methodology (inference‑only, fits a single RTX 6000 Pro Blackwell and a 10‑week timeline):**  

1. **Model selection & representation‑preservation measurement**  
   - Choose three representative released checkpoints: DiffuGPT‑S (127 M, GPT‑2‑based), DiffuLLaMA (6.74 B, LLaMA‑based), and Dream‑7B (7 B, LLaMA‑based).

   - On a held‑out text corpus (e.g., WikiText‑103 validation split), compute centered kernel alignment (CKA) between the hidden‑state representations of each DLM layer and the corresponding layer of its AR base model. Aggregate across layers (e.g., average CKA) to obtain a single **representation‑preservation score** per DLM.  
   - (Optional) Validate CKA with a lightweight linear‑probe task (next‑token prediction on a small probe set) to ensure robustness.

2. **Candidate generation across denoising‑step budgets**  
   - For each DLM, generate text samples using the model’s native diffusion sampler at three denoising‑step budgets: **low (16 steps)**, **medium (64 steps)**, and **high (256 steps)**.  
   - At each step budget, produce **N = 1, 4, 8** independent samples per prompt (using different random seeds).  
   - Prompts: a balanced mix of (i) HumanEval function signatures (for code infilling), (ii) GSM8K math word problems, and (iii) SIQA/WinoGrande commonsense questions (≈200 prompts total, stratified).

3. **Lightweight AR reranking**  
   - For every set of N samples per prompt, compute a score using a tiny AR scorer (GPT‑2‑small, 124 M parameters) via average negative log‑likelihood of the full generated sequence.  
   - Select the top‑ranked sample as the final output for that prompt under the “sampling + reranking” strategy.  
   - The “denoising‑only” baseline uses the single sample (N=1) generated at the given step budget without reranking.

4. **Quality and efficiency metrics**  
   - **Quality:** For each strategy (denoising‑only, sampling + reranking) compute three task‑specific scores:  
        * HumanEval pass@k (k=1,10) → averaged to a code score.  
        * GSM8K exact‑match accuracy.  
        * SIQA/WinoGrande accuracy (averaged).  
     - Normalize each score to [0,1] across all conditions, then take the **unweighted mean** to obtain a unified **Quality** metric.  
   - **Efficiency:** Measure **wall‑clock latency per generated token** (including scorer overhead for the reranking condition) averaged over all prompts and runs. Convert to **FLOPs‑equivalent** by multiplying latency by the GPU’s theoretical peak FP16 throughput (≈ 140 TFLOPs) to obtain an **Estimated Compute** value.  
   - Define the **Quality‑Efficiency Trade‑off (QET)** as **Quality / (Estimated Compute)**; higher QET indicates better quality per unit compute.

5. **Analysis**  
   - For each DLM, plot QET as a function of denoising steps (for denoising‑only) and as a function of sample count N (for sampling + reranking) at each step budget.  
   - Compute the **marginal QET gain** from (a) increasing denoising steps from low→medium→high (keeping N=1) and (b) increasing N from 1→4→8 (keeping steps fixed at the medium budget).  
   - Test whether higher representation‑preservation scores predict **larger marginal QET gains from sampling + reranking** and **smaller gains from additional denoising steps** using Spearman correlation across the three DLMs.  
   - Examine whether the correlation differs between GPT‑2‑based and LLaMA‑based models and whether it changes with the denoising‑step budget (interaction analysis).  
   - Perform a non‑parametric bootstrap (1 000 resamples) to obtain confidence intervals for correlation coefficients.
