**Method: Trajectory‑Aware Representation Alignment for Reranking (TARA)**  

**Rationale**  
The core question is whether a diffusion language model’s (DLM) fidelity to the autoregressive (AR) representations of its pretrained backbone predicts how much a lightweight, training‑free reranking step can recover the model’s accuracy headroom, and whether this recovery is more compute‑efficient than simply adding denoising steps. Existing proposals assess representation preservation by comparing *final* hidden‑state distributions (via CKA, linear probing, or subspace angles) or by measuring similarity of the *final* candidate hidden states to the AR model.  

A complementary—and as yet unexplored—angle is to examine **how the entire denoising trajectory** of a candidate aligns with the AR model’s hidden‑state dynamics. If a DLM preserves AR representations well, the intermediate hidden states it passes through during denoising should track the AR model’s hidden‑state evolution for the same prompt (when the AR model is run in teacher‑forcing mode). Candidates whose denoising trajectories stay close to the AR trajectory are therefore more likely to reflect the AR model’s knowledge and yield higher quality after a lightweight reranking step. By quantifying this trajectory‑level alignment we obtain a finer‑grained, step‑sensitive preservation signal that can directly inform reranking and let us test whether models with higher trajectory preservation benefit more from selection than from extra denoising steps.  

The proposed method proceeds as follows, staying strictly inference‑only, using only released checkpoints, and fitting within the compute and timeline constraints.

### Step‑by‑step Procedure  

| Step | Goal | Concrete Actions | Resources & Constraints |
|------|------|------------------|--------------------------|
| **0. Preparation** | Build a reproducible, inference‑only pipeline respecting hardware and timeline limits. | • Download the released DLM checkpoints (DiffuGPT‑S/M, DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B) and their AR base models (GPT‑2‑small/medium for GPT‑2‑based DLMs; LLaMA‑7B for LLaMA‑based DLMs). <br>• Tokenize a held‑out probing corpus (≈10 k sentences from WikiText‑103 + C4) with each model’s tokenizer; store token IDs. <br>• Assemble the benchmark suite (HumanEval, GSM8K, SIQA, WinoGrande) and implement a min‑max normalisation script that maps every raw metric to \([0,1]\) across all experimental conditions. <br>• Enable activation‑checkpointing and 8‑bit quantisation (`bitsandbytes`) for the 6.74B DiffuLLaMA so it fits in the 96 GB GPU with batch‑size ≥ 4. <br>• Split work among the three GPU‑enabled team members: each owns a subset of models/step‑budgets and writes results to a shared CSV/Parquet store. | One RTX 6000 Pro Blackwell (96 GB), 8‑bit quantisation + activation checkpointing, CPU‑only work for data prep/eval harnesses. |
| **1. Quantify trajectory‑level AR‑representation preservation** | Obtain a scalar preservation score \(P_i\) that reflects how closely the *denoising trajectory* of a DLM mirrors the AR model’s hidden‑state evolution. | **1.1 Frozen forward passes** – For each sentence in the probing corpus, run the DLM **inference‑only** with a fixed denoising budget (e.g., 32 steps, chosen because marginal returns are still informative). At each denoising step \(t\) and each Transformer layer \(\ell\), capture the post‑attention hidden‑state tensor \(\mathbf{H}^{\text{DLM}}_{i,\ell,t} \in \mathbb{R}^{N\times D}\) (where \(N\) is the number of tokens in the sentence). <br>**1.2 AR reference trajectory** – Using the same token IDs, run the frozen AR base model in teacher‑forcing mode (the model sees the ground‑truth token sequence and predicts the next token at each position). For each layer \(\ell\) collect the hidden‑state tensor \(\mathbf{H}^{\text{AR}}_{\ell} \in \mathbb{R}^{N\times D}\) (the AR model does not have a denoising schedule, so we treat its single forward pass as the reference at every step). <br>**1.3 Similarity per step & layer** – Compute **linear CKA** between \(\mathbf{H}^{\text{DLM}}_{i,\ell,t}\) and \(\mathbf{H}^{\text{AR}}_{\ell}\). This yields a similarity value \(s_{i,\ell,t}\in[0,1]\) (higher = better alignment). <br>**1.4 Aggregation** – Weight deeper layers more (exponential decay with depth) and later denoising steps more (linear increase with \(t\)) because they carry higher‑level semantics and reflect the final refinement. The final preservation score is: <br>\[
P_i = \frac{\sum_{\ell,t} w_\ell \, v_t \, s_{i,\ell,t}}{\sum_{\ell,t} w_\ell \, v_t},
\] <br>where \(w_\ell = \exp(\alpha \cdot \ell)\) (with \(\alpha\) tuned to give deeper layers ~2× weight of shallowest) and \(v_t = t / T\) (with \(T\) the max denoising steps used). <br>**1.5 Implementation note** – All CKA computations are performed on CPU using the captured tensors; no gradients are involved, and the linear‑algebra cost is negligible compared to generation. | No gradient updates; only forward passes and lightweight linear algebra (CKA on matrices of size ≤ \(N\times D\)). All steps run on CPU or the same GPU used for generation. |
| **2. Multi‑candidate generation** | Produce a diverse set of outputs for each prompt at several denoising‑step budgets. | • Select a prompt set covering the three benchmark families (e.g., 200 HumanEval prompts, 200 GSM8K questions, 200 SIQA/WinoGrande items). <br>• For each DLM \(i\) and each denoising‑step budget \(S \in \{16,32,64,128\}\): <br> - Sample **K = 8** candidates per prompt using nucleus sampling (top‑p = 0.9) to ensure diversity while staying close to the model’s distribution. <br> - During generation, store the hidden‑state tensors \(\mathbf{H}^{\text{DLM}}_{i,\ell,t}\) for each layer \(\ell\) and step \(t\) (these are needed for Step 3). <br>• Use a fixed random seed across models to make candidate sets comparable. | Pure inference; batch size limited by GPU memory (≈ 4‑8 sequences per step). Storing hidden states for K = 8 candidates adds modest memory overhead (still fits within 96 GB with activation checkpointing). |
| **3. Trajectory‑aware candidate scoring** | Score each candidate by how closely its denoising trajectory aligns with the AR model’s reference trajectory. | **3.1 Per‑candidate similarity** – For a given candidate, we already have its hidden‑state tensors \(\mathbf{H}^{\text{DLM}}_{i,\ell,t}\) from Step 2. Compute linear CKA between each \(\mathbf{H}^{\text{DLM}}_{i,\ell,t}\) and the AR reference \(\mathbf{H}^{\text{AR}}_{\ell}\) (same as in Step 1.3), obtaining \(s^{\text{cand}}_{i,\ell,t}\). <br>**3.2 Aggregation** – Apply the same layer‑ and step‑weighting scheme used for \(P_i\) to obtain a candidate‑level trajectory alignment score: <br>\[
\text{TrajScore}_{i,c} = \frac{\sum_{\ell,t} w_\ell \, v_t \, s^{\text{cand}}_{i,\ell,t}}{\sum_{\ell,t} w_\ell \, v_t}.
\] <br>**3.3 Optional hybrid scoring** – To capture token‑level likelihood as well, compute the average negative log‑likelihood (NLL) of the candidate under a tiny AR scorer (GPT‑2‑small, 124 M). Combine the two signals via a lightweight ridge‑regression meta‑learner trained **only on CPU** using a held‑out validation subset of the probing corpus: <br>\[
\text{FinalScore}_{i,c}= \beta_0 + \beta_1 \,\text{TrajScore}_{i,c} + \beta_2 \,\text{(-NLL)}.
\] <br>The meta‑learner has < 0.1 M parameters; training is a one‑time CPU operation and does not involve the DLM. <br>**3.4 Ranking** – Sort the K candidates in descending order of FinalScore (or TrajScore if the hybrid is omitted); the top‑1 after this sort is the *trajectory‑aware reranked* output. <br>**3.5 Cost measurement** – Record the forward‑pass time of the AR scorer per candidate (< 0.5 ms for GPT‑2‑small, ≈ 2 ms for 8‑bit LLaMA‑7B). The extra cost of computing TrajScore is merely a few CPU‑based CKA operations per candidate (negligible). | Only forward passes through the DLM (already done) and the frozen AR scorer; no training of the DLM. Linear CKA and ridge regression are CPU‑only. |
| **4. Quality measurement** | Map raw outputs to a unified, comparable score. | • For each benchmark compute: <br> - HumanEval: pass@k for k = 1,10. <br> - GSM8K: exact‑match accuracy. <br> - SIQA & WinoGrande: accuracy (multiple‑choice). <br>• Normalise each raw score to \([0,1]\) across **all** model‑step‑budget‑reranking conditions (min‑max scaling). <br>• Define the **Unified Quality Score (UQS)** as the arithmetic mean of the four normalised components (HumanEval@1, HumanEval@10, GSM8K, (SIQA+WinoGrande)/2). <br>• Also compute the *oracle* UQS (the best candidate among the K generated) to quantify the accuracy headroom for each condition. | All metrics computed offline on CPU; no extra GPU load. |
| **5. Experimental contrasts** | Isolate the two sources of improvement: (a) trajectory‑aware reranking vs. (b) more denoising steps. | For each DLM \(i\) and low step budget \(S_{\text{low}}=16\): <br> - **Reranking gain**: \(\Delta^{\text{rank}}_{i,S_{\text{low}}} = \text{UQS}_{i,S_{\text{low}}}^{\text{ranked}} - \text{UQS}_{i,S_{\text{low}}}^{\text{top‑1}}\). <br> - **Denoising‑step gain** (no reranking): \(\Delta^{\text{step}}_{i} = \text{UQS}_{i,128}^{\text{top‑1}} - \text{UQS}_{i,16}^{\text{top‑1}}\). <br>• Compute the *relative efficiency* \(\eta_i = \frac{\Delta^{\text{rank}}_{i,S_{\text{low}}}}{\Delta^{\text{step}}_{i}}\) (values > 1 indicate reranking yields more quality per unit of added compute). | Requires only the four step budgets; no additional model runs. |
| **6. Statistical modelling** | Test whether trajectory‑level preservation predicts reranking advantage and whether this differs by architecture or step budget. | Fit a **linear mixed‑effects model** (LME) with UQS as the dependent variable: <br>\[
\text{UQS}_{ijk\ell}= \beta_0 + \beta_1 P_i + \beta_2 S_j + \beta_3 R_{k} + \beta_4 (P_i \times S_j) + \beta_5 (P_i \times R_{k}) + \beta_6 (S_j \times R_{k}) + \beta_7 A_i + \beta_8 (P_i \times A_i) + u_i + \epsilon_{ijk\ell}
\] <br>where: <br>• \(P_i\) = trajectory‑preservation score from Step 1 (continuous). <br>• \(S_j\) = denoising‑step budget (log‑scaled continuous). <br>• \(R_k\) = reranking indicator (0 = top‑1, 1 = trajectory‑aware reranked). <br>• \(A_i\) = architecture dummy (0 = GPT‑2‑based, 1 = LLaMA‑based). <br>• \(u_i\sim\mathcal{N}(0,\sigma^2_{\text{model}})\) captures model‑specific random intercepts. <br>Key hypotheses: <br> - **H1**: \(\beta_5 > 0\) (reranking yields larger gains when trajectory preservation is high). <br> - **H2**: \(\beta_8 \neq 0\) (the preservation‑reranking relationship differs between GPT‑2‑ and LLaMA‑based DLMs). <br> - **H3**: \(\beta_4 > 0\) (the benefit of extra steps grows with preservation). <br>• Additionally, compute Spearman’s \(\rho\) between \(P_i\) and the relative efficiency \(\eta_i\) to directly address the core research question. <br>Inference performed with `statsmodels` (frequentist) or `brms`/`rstanarm` (Bayesian) on CPU. | All modelling done on CPU; no extra GPU time required. |
| **7. Efficiency accounting** | Translate quality gains into comparable compute cost. | • Measure wall‑clock time for a single denoising step (averaged over 100 runs) for each DLM (with activation checkpointing & 8‑bit quant). <br>• Compute **cost per step**: \(C^{\text{step}}_i = t^{\text{step}}_i\). <br>• Compute **cost of reranking**: \(C^{\text{rank}}_i = K \times t^{\text{scorer}}_i\) (AR forward pass per candidate) + negligible CPU CKA cost. <br>• Define **efficiency ratio**: \(\displaystyle \epsilon_i = \frac{\Delta^{\text{rank}}_{i,S_{\text{low}}} / C^{\text{rank}}_i}{\Delta^{\text{step}}_{i} / (C^{\text{step}}_i \times (128-16))}\). <br>Values > 1 indicate reranking gives more quality per FLOP/second than adding denoising steps. | Timing measurements are cheap (< 5 min total). |
| **8. Ablation & robustness checks** | Verify that findings are not artefacts of specific choices. | • Vary the layer‑weighting \(\alpha\) and step‑weighting scheme (uniform, exponential, inverse) to test sensitivity of \(P_i\) and TrajScore. <br>• Replace linear CKA with **Procrustes similarity** or **SVCCA** as alternative alignment metrics in Steps 1 and 3. <br>• Change nucleus sampling p (0.8, 0.95) and K (4, 16) to test sensitivity to candidate diversity. <br>• Run a *control* where the AR scorer is replaced by a random scorer (same dimensionality) to ensure gains are not due to chance ordering. <br>• Test alternative tiny scorers (DistilGPT‑2, MiniLM) to confirm the < 1 % FLOP claim. | All ablations reuse the same generated candidate pool; no extra generation needed. |
| **9. Reporting & reproducibility** | Ensure transparent dissemination. | • Archive all scripts, random seeds, and environment specifications (Dockerfile or Conda yaml). <br>• Publish the extracted hidden‑state features (optional) and the final results table on an open repository (e.g., HuggingFace datasets + Zenodo). <br>• Provide a short “re‑run” notebook that reproduces the key figures (preservation vs. reranking gain, efficiency ratio). | Fits the ten‑week timeline: weeks 1‑2 for setup, weeks 3‑5 for generation & scoring, week 6 for metric computation, weeks 7‑8 for statistical analysis, weeks 9‑10 for write‑up and reproducibility packaging. |

### Why TARA is substantively different  

- **Trajectory‑level focus**: Prior proposals (1, 2, 6) measured similarity between *final* hidden states or used subspace angles on static representations. TARA evaluates the *entire denoising trajectory* of each candidate against the AR model’s hidden‑state evolution, capturing how faithfully the DLM follows the AR decoding path at intermediate steps.  
- **Hybrid scoring option**: While a pure trajectory score is used for reranking, we also offer a lightweight ridge‑regression fusion with token‑level NLL from a tiny AR scorer—still inference‑only for the DLM—providing a nuanced quality signal that prior work did not explore.  
- **Novel preservation metric**: The preservation score \(P_i\) aggregates CKA across denoising steps and layers with explicit step‑weighting, yielding a more sensitive predictor of reranking benefit than a single‑step CKA or linear probe.  
- **Clear efficiency accounting**: By measuring the actual wall‑clock cost of the trajectory‑based scoring (which is merely CPU‑side CKA) we can directly compare it to the cost of additional denoising steps, addressing the efficiency question in a way that the earlier methods did not.  

TARA therefore offers a fresh mechanistic lens—alignment of the *dynamic* generation process with the AR backbone—to answer whether representation preservation governs the effectiveness of lightweight selection versus extra denoising, while remaining fully compatible with the inference‑only, resource‑constrained setting outlined in the problem statement.
