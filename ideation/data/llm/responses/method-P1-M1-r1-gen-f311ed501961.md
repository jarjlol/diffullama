**Method**

| Step | Goal | Concrete actions | Resources & Constraints |
|------|------|------------------|--------------------------|
| **0. Preparation** | Build an inference‑only, reproducible pipeline that respects hardware and timeline limits. | • Download the released checkpoints: DiffuGPT‑S/M, DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B and the corresponding AR base models (GPT‑2‑small/medium, LLaMA‑7B). <br>• Tokenise a *held‑out probing corpus* (10 k sentences randomly sampled from WikiText‑103 + C4) **once** with each model’s tokenizer and store the token IDs. <br>• Assemble the downstream benchmark suite (HumanEval, GSM8K, SIQA, WinoGrande) and write a evaluation harness that (i) extracts answers, (ii) computes raw scores, and (iii) normalises each benchmark to \([0,1]\) **separately** (min‑max across all conditions for that benchmark). <br>• For the largest model (DiffuLLaMA‑6.74B) enable activation‑checkpointing and 8‑bit quantisation (`bitsandbytes`) so that a batch of ≥4 sequences fits in the 96 GB GPU. <br>• Parallelise work across the three GPU‑enabled team members: each member owns a disjoint subset of (model, step‑budget) pairs and writes results to a shared Parquet/CSV store. <br>• Fix all random seeds (numpy, torch, CUDA) and log them; store the environment (conda yaml + Dockerfile). | One RTX 6000 Pro Blackwell (96 GB), 8‑bit quantisation, activation checkpointing, CPU‑only work for data‑prep/eval harnesses. |
| **1. Quantify AR‑representation preservation** | Obtain a scalar “preservation score” \(P_i\) for each DLM that reflects similarity of its hidden‑state geometry to that of its AR backbone. | **1.1 Feature extraction** – For every sentence in the probing corpus, run the DLM **inference‑only** (no gradient) and collect the hidden‑state tensor of each Transformer layer **after the attention sub‑layer and before the feed‑forward** (the residual stream). Do the same with the frozen AR base model (same token IDs, same sequence length). <br>**1.2 Similarity metrics per layer** – Compute both: <br> • **Centered Kernel Alignment (CKA)** with a linear kernel between the DLM and AR hidden‑state matrices (\(N\times D\)). <br> • **Linear probing**: fit a ridge‑regression model (no gradient to the DLM) to predict AR hidden states from DLM hidden states; record the coefficient of determination \(R^2\). <br>**1.3 Layer weighting** – Assign weight \(w_\ell = \exp\bigl(-\lambda \cdot \frac{L-\ell}{L}\bigr)\) to layer \(\ell\) (where \(L\) = total number of layers, \(\ell=1\) is the first layer). We set \(\lambda = 0.5\) so that deeper layers receive roughly twice the weight of the shallowest layer; this choice is reported and can be varied in ablation. <br>**1.4 Aggregation** – Compute the weighted average of CKA across layers: \(P_i^{\text{CKA}} = \sum_{\ell} w_\ell \,\text{CKA}_\ell / \sum_\ell w_\ell\). Do the same for \(R^2\) to obtain \(P_i^{\text{probe}}\). The primary preservation score is \(P_i = P_i^{\text{CKA}}\); the probing score is retained as a secondary, complementary measure. | No training; only forward passes. Ridge regression solved analytically on CPU (scikit‑learn). |
| **2. Multi‑candidate generation** | Produce a diverse set of outputs for each prompt at several denoising‑step budgets. | • Build a prompt set that mirrors the three benchmark families: 200 HumanEval prompts, 200 GSM8K questions, 200 SIQA/WinoGrande items (total 600 prompts). <br>• For each DLM and each denoising‑step budget \(S \in \{16,32,64,128\}\): <br> - Sample **K = 8** candidates per prompt using nucleus sampling with \(p=0.9\) (ensures diversity while staying close to the model distribution). <br> - Store the raw token sequences; optionally keep the per‑step denoising trace for later analysis. <br>• Use the same global random seed across all models so that candidate sets are comparable. | Generation is pure inference; batch size limited by GPU memory (≈ 4‑8 sequences per step). |
| **3. Lightweight, training‑free reranking** | Apply a tiny AR scorer to reorder candidates and compute the selection gain. | • Load **two** scorers to break scorer‑model family confounding: <br> - **GPT‑2‑small** (124 M) – serves as the baseline scorer used in the original proposal. <br> - **LLaMA‑7B** (or a 1‑B distilled version if memory‑tight) – serves as a cross‑family scorer for GPT‑2‑based DLMs and vice‑versa. <br>• For each candidate, compute the **average negative log‑likelihood** (or perplexity) under the scorer; lower score = higher likelihood. <br>• Rank candidates ascending by this score; the top‑1 after reranking is the *selected* output. <br>• Measure the scorer’s FLOPs and wall‑clock time (≈ 0.3 % of a single denoising step for the largest DLM; < 1 ms per candidate). | Scorers fit easily in memory; latency contribution negligible (< 1 ms per candidate). |
| **4. Quality measurement** | Translate raw outputs into a unified, comparable metric while preserving benchmark‑specific information. | • Compute raw scores per benchmark: <br> - **HumanEval**: pass@1 and pass@10 (standard unit‑test harness). <br> - **GSM8K**: exact‑match accuracy after answer extraction. <br> - **SIQA & WinoGrande**: multiple‑choice accuracy. <br>• **Normalisation** – For each benchmark separately, apply min‑max scaling across *all* model‑step‑budget‑reranking conditions (i.e., the worst observed score maps to 0, the best to 1). This yields comparable \([0,1]\) scores that are **independent of the particular run** because the min‑max is computed on the full experimental matrix and stored for reuse. <br>• **Unified Quality Score (UQS)** – Derive data‑driven weights by running a PCA on the four normalised benchmark scores on a held‑out validation split (10 % of the prompts) and taking the first principal component as the weighting vector (ensures the UQS captures the dominant shared variance without imposing arbitrary equal weights). The UQS is the weighted sum of the four normalised scores. <br>• Also compute the **oracle UQS** (best candidate among the K generated) to quantify the *accuracy headroom* for each condition. | All scoring and normalisation performed offline on CPU; no extra GPU load. |
| **5. Experimental contrasts** | Isolate the two sources of improvement: (a) reranking vs. (b) more denoising steps. | For each DLM \(i\) and low step budget \(S_{\text{low}}=16\): <br> - **Reranking gain**: \(\Delta^{\text{rank}}_{i,S_{\text{low}}} = \text{UQS}_{i,S_{\text{low}}}^{\text{ranked}} - \text{UQS}_{i,S_{\text{low}}}^{\text{top‑1}}\). <br> - **Denoising‑step gain** (no reranking): \(\Delta^{\text{step}}_{i} = \text{UQS}_{i,128}^{\text{top‑1}} - \text{UQS}_{i,16}^{\text{top‑1}}\). <br>• **Relative efficiency (gain‑ratio)**: \(\eta_i = \dfrac{\Delta^{\text{rank}}_{i,S_{\text{low}}}}{\Delta^{\text{step}}_{i}}\) (values > 1 indicate reranking yields more quality per added denoising step). <br>• **Compute‑normalised efficiency**: measure wall‑clock time per denoising step \(t^{\text{step}}_i\) (averaged over 100 runs) and scorer time per candidate \(t^{\text{scorer}}_i\). Define <br> \(\epsilon_i = \dfrac{\Delta^{\text{rank}}_{i,S_{\text{low}}} / (K \cdot t^{\text{scorer}}_i)}{\Delta^{\text{step}}_{i} / \bigl(t^{\text{step}}_i \times (128-16)\bigr)}\). <br> Values > 1 mean reranking delivers more quality per unit of compute than adding denoising steps. | Requires only the four step budgets; no additional model runs. Timing measurements are cheap (< 5 min total). |
| **6. Statistical modelling** | Test whether preservation predicts reranking advantage and whether this differs by architecture or step budget, while accounting for limited model count. | • Create a tidy table with one row per (model, step budget, reranking condition, prompt). <br>• **Fixed‑effects only model** (to avoid confounding between model‑level random intercepts and the preservation score, which is also model‑level): <br>\[
\text{UQS}_{ijkl}= \beta_0 + \beta_1 \tilde{P}_i + \beta_2 \log(S_j) + \beta_3 R_k + \beta_4 (\tilde{P}_i \times \log(S_j)) + \beta_5 (\tilde{P}_i \times R_k) + \beta_6 (\log(S_j) \times R_k) + \beta_7 A_i + \beta_8 (\tilde{P}_i \times A_i) + \epsilon_{ijkl}
\] <br>where: <br> - \(\tilde{P}_i\) = preservation score **centered** (mean = 0). <br> - \(S_j\) = denoising‑step budget (treated as log‑scaled continuous). <br> - \(R_k\) = reranking indicator (0 = top‑1, 1 = reranked). <br> - \(A_i\) = architecture dummy (0 = GPT‑2‑based, 1 = LLaMA‑based). <br> - \(\epsilon\) ∼ N(0,σ²). <br>• Estimate parameters by ordinary least squares; obtain **bias‑corrected bootstrap confidence intervals** (10 000 resamples) for each coefficient. <br>• **Key hypotheses**: <br> H1: \(\beta_1 > 0\) (higher preservation → higher baseline quality). <br> H2: \(\beta_4 > 0\) (benefit of extra steps grows with preservation). <br> H3: \(\beta_5 > 0\) (reranking yields larger gains when preservation is high). <br> H4: \(\beta_8 \neq 0\) (the preservation‑reranking relationship differs between architectures). <br>• As a sensitivity check, fit a **Bayesian linear regression** with weakly informative priors (Normal(0,2.5) for coefficients, Half‑Cauchy(0,2.5) for σ) and report posterior means and 95 % credible intervals. <br>• Additionally, compute **Spearman’s ρ** between \(P_i\) and the gain‑ratio \(\eta_i\) (and between \(P_i\) and \(\epsilon_i\)) to directly address the research question. | All modelling performed on CPU (statsmodels, pymc3/bootstrapped). |
| **7. Efficiency accounting** | Translate quality gains into comparable compute cost for practical decision‑making. | • Report **absolute** gains (\(\Delta^{\text{rank}}\), \(\Delta^{\text{step}}\)) alongside the ratios \(\eta_i\) and \(\epsilon_i\). <br>• Provide a table showing **quality per second** (QPS) for each lever: <br> QPS\(_{\text{rank}} = \Delta^{\text{rank}} / (K \cdot t^{\text{scorer}})\) <br> QPS\(_{\text{step}} = \Delta^{\text{step}} / (t^{\text{step}} \times (128-16))\). <br>• Discuss scenarios where a fixed inference budget (e.g., 200 ms) would be better spent on reranking vs. extra denoising steps. | Timing measurements already collected in Step 5; negligible extra cost. |
| **8. Ablation & robustness checks** | Verify that findings are not artefacts of specific choices. | • **Scorer size** – repeat Step 3 with GPT‑2‑medium (355 M) and DistilGPT‑2 (82 M) to confirm the < 1 % FLOP claim and test whether scorer capacity influences the preservation‑gain relationship. <br>• **Alternative preservation metrics** – compute SVCCA, Procrustes similarity, and centered kernel alignment with an RBF kernel; compare rankings of \(P_i\). <br>• **Candidate diversity** – vary nucleus \(p\) (0.8, 0.95) and \(K\) (4, 16); compute pairwise self‑BLEU entropy to quantify diversity and test whether diversity mediates the preservation‑gain link. <br>• **Generation‑domain probing set** – extract 2 k tokens from the actual benchmark prompts (HumanEval + GSM8K) and recompute preservation scores; report correlation with the original WikiText‑based scores. <br>• **Control scorer** – replace the AR scorer with a random scorer (uniform scores) to ensure observed gains are not due to chance ordering. <br>• **Normalization reference** – repeat the analysis using a *fixed* reference set (e.g., the first 10 % of prompts) for min‑max scaling to confirm that results are robust to the choice of normalization pool. | All ablations reuse the same generated candidate pool; no extra generation needed. |
| **9. Reporting & reproducibility** | Ensure transparent dissemination and enable replication. | • Archive all scripts, random seeds, and environment specifications (conda yaml + Dockerfile). <br>• Store the extracted hidden‑state features (optional) and the final results table on an open repository (HF datasets + Zenodo). <br>• Provide a short “re‑run” notebook that reproduces the key figures: preservation vs. reranking gain, efficiency ratios, and the bootstrap‑derived coefficient plots. <br>• Include a **pre‑registration** document (OSF) outlining the primary hypotheses, analysis plan, and correction for multiple tests (we report family‑wise error‑controlled p‑values via the bootstrap max‑t method). | Fits the ten‑week timeline: weeks 1‑2 for setup, weeks 3‑5 for generation & scoring, week 6 for metric computation & normalisation, week 7‑8 for statistical analysis & efficiency accounting, weeks 9‑10 for ablation, write‑up, and reproducibility packaging. |

**Rationale**

The revised method directly answers the core question: *Does the extent to which a diffusion language model (DLM) retains the autoregressive (AR) representations of its pretrained backbone determine how much a lightweight, training‑free reranking step can recover the model’s accuracy headroom, and is this recovery more efficient than simply adding denoising steps?*  

1. **Linking representation preservation to reranking potential** – We compute both CKA (a symmetric, scale‑invariant similarity measure) and linear probing on a held‑out text corpus. CKA is taken as the primary preservation score because it captures geometric similarity without requiring a predictive model, thereby reducing bias toward the scorer architecture. The linear‑probe score is retained as a complementary, interpretable check. Layer‑wise aggregation uses an explicit exponential decay (\(\lambda=0.5\)) that gives deeper semantic layers higher influence, a choice justified by prior work showing that later layers encode more task‑relevant information and is varied in ablation.

2. **Isolating the two improvement levers** – By generating multiple candidates at four denoising‑step budgets and applying a tiny AR scorer, we obtain (a) the *selection gain* (reranking over a fixed candidate set) and (b) the *denoising‑step gain* (more steps, no reranking). The gain‑ratio \(\eta_i\) and the compute‑normalised ratio \(\epsilon_i\) let us compare quality improvement per unit of added compute, directly addressing the efficiency clause of the research question.

3. **Addressing scorer‑model family confounding** – Using both GPT‑2‑small and a LLaMA‑based scorer (or distilled version) lets us test whether the preservation‑gain relationship holds when the scorer architecture differs from the DLM’s backbone. This mitigates the circularity highlighted in the reviews and enables a cross‑family analysis.

4. **Robust statistical inference with limited models** – With only five DLM checkpoints, a random‑effects term would confound with the preservation score. We therefore employ a fixed‑effects linear model with the preservation score centered, and obtain bias‑corrected bootstrap confidence intervals (10 000 resamples) for all coefficients. A Bayesian regression with weakly informative priors serves as a sensitivity check. This approach controls Type I error while still testing the key interactions (preservation × step, preservation × reranking, preservation × architecture).

5. **Unified yet transparent quality metric** – Rather than arbitrarily averaging four heterogeneous benchmarks, we derive data‑driven weights from a PCA on a validation split, ensuring the UQS reflects the dominant shared variance. We also report per‑benchmark normalised scores and the oracle UQS, so readers can inspect domain‑specific patterns.

6. **Efficiency accounting made explicit** – We provide both absolute gains and the two efficiency ratios (\(\eta_i\) and \(\epsilon_i\)), clearly defining their denominators (extra denoising steps vs. scorer compute). This removes ambiguity about what “more efficient than increasing the denoising‑step budget” means and allows practitioners to decide where to allocate a fixed inference budget.

7. **Comprehensive ablation and robustness** – We vary scorer size, alternative preservation metrics, candidate‑diversity settings, normalization pools, and even add a generation‑domain probing set to verify that preservation scores are not artefacts of the probing corpus. A random‑scorer control confirms that gains are not due to chance ordering.

8. **Adherence to inference‑only constraint** – All steps rely solely on forward passes of released checkpoints; the only learned component (ridge regression) is solved analytically on CPU and does not modify any model weights. No continual pre‑training, fine‑tuning, or adaptation is performed, satisfying the team decision D‑2026‑09‑21‑a.

9. **Feasibility within the given resources** – Activation checkpointing and 8‑bit quantisation enable the 6.74B DiffuLLaMA to run on a single 96 GB GPU with batch size ≥4. Generation is capped at 128 steps, a range where the target paper shows informative marginal returns. Parallelising across three GPU‑enabled team members keeps wall‑clock time well under the ten‑week limit, while CPU‑heavy tasks (feature extraction, probing, evaluation, statistical modelling) are distributed to the remaining four members.

10. **Generalisability** – The protocol is model‑agnostic: any DLM released with an associated AR base can be plugged in. The preservation metrics (CKA, linear probing, SVCCA, Procrustes) and the lightweight scorers (GPT‑2‑family, LLaMA‑family) are interchangeable. The unified quality metric can be recomputed with alternative benchmarks or weighted schemes, and the statistical framework accommodates additional architectures (e.g., Mamba‑based diffusion) or alternative lightweight scorers without redesign.

By tightly integrating representation‑alignment analysis with a rigorous, efficiency‑focused comparison of lightweight selection versus extra denoising, this method moves beyond empirical tuning to provide a mechanistic explanation for why some DLMs benefit more from reranking than others. It bridges the representation‑alignment literature (REPR‑ALIGN, PreDiff‑LM) with pure inference‑time trade‑off work (Jacobi Forcing, TESS 2), offering actionable insight for future DLM design and deployment.
