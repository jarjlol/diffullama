**Method:**  
**Coarse‑to‑Fine AR‑Guided Refinement (CFAR)** – an inference‑only strategy that first generates a large, cheap pool of diffusion candidates, scores them with a frozen autoregressive (AR) base model, and then reallocates the remaining compute budget to denoise only the most promising candidates for additional steps. By explicitly separating *candidate exploration* (controlled by the initial pool size \(N_{\text{coarse}}\)) from *candidate refinement* (controlled by the extra denoising steps \(S_{\text{fine}}\) given to the top‑\(K\) candidates), CFAR provides a principled way to trade off denoising‑step budget against the number of generation candidates while using a lightweight AR reranker to guide where compute is spent.

---

### Rationale  
The target paper identifies two open issues:  

1. **Accuracy headroom (L6)** – performance can be improved either by more denoising steps or by better exploitation of the model’s candidate diversity.  
2. **Compute‑normalized efficiency gap (L9)** – existing efficiency claims are not FLOP‑normalized, so it is unclear whether DLMs truly beat AR models when the same compute is spent.  

Recent inference‑time tricks (Jacobi Forcing, TESS 2 reward guidance) show that compute can be shifted between denoising and selection, but it remains unknown whether the headroom is best closed by (a) uniformly increasing denoising steps for all candidates, (b) simply generating and reranking more candidates, or (c) a *hybrid* approach that spends cheap compute on many diverse samples and then focuses expensive refinement on the most promising ones.  

CFAR directly addresses this question:  
- **Coarse stage** (many candidates, few steps) explores the output space cheaply, maximizing candidate diversity.  
- **AR scorer** provides a lightweight, proxy signal of task‑relevant quality (fluency, logical consistency) without any model update.  
- **Fine stage** (few candidates, many steps) refines the top‑\(K\) candidates, converting the diversity explored in the coarse stage into higher‑quality outputs.  

By sweeping over \((N_{\text{coarse}}, S_{\text{fine}})\) under a fixed total FLOP budget, we can trace the Pareto frontier of quality versus compute and quantify whether the hybrid allocation dominates the two extremes (uniform step increase vs. pure candidate expansion). The method remains strictly inference‑only, uses only publicly released checkpoints, and can be implemented within the ten‑week timeline on a single RTX 6000 Pro Blackwell by parallelizing candidate generation and scoring across the three GPU‑enabled team members.

## 1. Model and Checkpoint Preparation  
- Assemble the five released DLMs: **DiffuGPT‑S/M**, **DiffuLLaMA‑6.74B**, **Dream‑7B**, **LLaDA‑8B**, **DiffuCoder‑7B**.  
- For each DLM obtain its corresponding AR base model (GPT‑2‑small/medium for the GPT‑2‑based DLMs; LLaMA‑7B for the LLaMA‑based DLMs).  
- Verify tokenizer compatibility; if the diffusion checkpoint uses a different tokenizer, replace it with the AR base’s tokenizer (no weight change, still inference‑only).  
- Load **one diffusion model and its AR scorer** in FP16 on the RTX 6000 Pro Blackwell at a time; this fits comfortably within the 96 GB memory budget.

## 2. Unified Quality Metric (UQM)  
- For each benchmark (HumanEval pass@1, pass@10; GSM8K; SIQA; WinoGrande) compute the raw score per model‑condition.  
- Apply **min‑max normalization within each benchmark** across all conditions so that the worst score maps to 0 and the best to 1.  
- UQM = average of the five normalized scores → a dimensionless quality score in [0, 1] where each benchmark contributes equally.  
- In addition to the scalar UQM, report per‑benchmark normalized scores to expose any domain‑specific effects.

## 3. Compute‑Normalized Efficiency Measurement  
- **Diffusion FLOPs per denoising step (full sequence)**:  
  \[
  F_{\text{diff}} = \alpha \times |\theta| \times L
  \]  
  where \(\alpha\approx2\) (multiply‑add), \(|\theta|\) = diffusion parameter count, \(L=128\) (fixed sequence length).  
- **AR scorer FLOPs per evaluation**: a single forward pass of the frozen AR base model over the sequence (≈ 1 % of \(F_{\text{diff}}\)).  
- **Total FLOPs for a condition**:  
  \[
  \text{FLOPs}_{\text{total}} = 
  N_{\text{coarse}}\times S_{\text{coarse}}\times F_{\text{diff}} \;+\;
  K \times S_{\text{fine}} \times F_{\text{diff}} \;+\;
  \bigl(N_{\text{coarse}} + K\bigr) \times F_{\text{AR}}
  \]  
  where \(S_{\text{coarse}}\) is the small number of steps used for every candidate in the coarse pool, \(S_{\text{fine}}\) is the additional number of steps given to each of the top‑\(K\) candidates, and \(F_{\text{AR}}\) is the FLOP cost of one AR forward pass.  
- **Wall‑clock validation**: run a 100‑token warm‑up, then measure average latency per generated token (including all denoising passes, AR scoring, and bookkeeping) using CUDA events; verify linearity between measured latency and FLOP estimate (R² > 0.95).  
- Report efficiency as **quality per FLOP** (or quality per millisecond) for each condition.

## 4. Coarse‑to‑Fine AR‑Guided Refinement Procedure (CFAR)  

| Symbol | Meaning |
|--------|---------|
| \(N_{\text{coarse}}\) | initial pool size (∈ {1, 2, 4, 8, 16}) |
| \(S_{\text{coarse}}\) | denoising steps for every coarse candidate (∈ {4, 8, 16}) |
| \(K\) | number of top candidates selected for refinement (∈ {1, 2, 4}) |
| \(S_{\text{fine}}\) | additional denoising steps applied to each selected candidate (∈ {8, 16, 32, 64}) |
| \(\text{AR‑score}(x)\) | average negative log‑likelihood (NLL) of sequence \(x\) under the frozen AR base model (lower = higher quality) |
| \(B\) | total compute budget in FLOPs (varied to trace the Pareto front) |

**Algorithm (per prompt):**  

1. **Coarse generation**  
   - Sample \(N_{\text{coarse}}\) independent noise tensors \(\{\mathbf{z}^{(i)}_{T}\}_{i=1}^{N_{\text{coarse}}}\).  
   - Run the diffusion reverse process for exactly \(S_{\text{coarse}}\) steps on each tensor, obtaining coarse sequences \(\{\mathbf{x}^{(i)}_{\text{coarse}}\}\).  
   - Compute the AR‑score (average NLL) for each coarse candidate.  

2. **Selection**  
   - Rank the coarse candidates by AR‑score (ascending NLL).  
   - Keep the top‑\(K\) candidates as the *refinement set*; discard the rest.  

3. **Fine refinement**  
   - For each of the \(K\) selected candidates, continue the diffusion reverse process from the current latent for an additional \(S_{\text{fine}}\) steps, yielding refined sequences \(\{\mathbf{x}^{(j)}_{\text{fine}}\}_{j=1}^{K}\).  
   - (Optionally) recompute AR‑score on the refined sequences; the final output for the prompt is the refined candidate with the lowest NLL.  

4. **Compute accounting**  
   - The total FLOPs consumed are exactly the expression in Section 3.  
   - By varying \((N_{\text{coarse}}, S_{\text{coarse}}, K, S_{\text{fine}})\) while holding the total budget \(B\) constant, we obtain a family of points that trace the trade‑off between exploration (more coarse candidates) and exploitation (more refinement steps).  

**Explored conditions**  
- \(N_{\text{coarse}} \in \{1,2,4,8,16\}\)  
- \(S_{\text{coarse}} \in \{4,8,16\}\) (kept small to keep the coarse stage cheap)  
- \(K \in \{1,2,4\}\) (number of candidates promoted to refinement)  
- \(S_{\text{fine}} \in \{8,16,32,64\}\) (additional steps for refinement)  
- The total budget \(B\) is set to a series of values ranging from ~0.5× to 4× the FLOPs of a uniform baseline (e.g., \(N=1, S=S_{\text{coarse}}+S_{\text{fine}}\)). For each \(B\) we enumerate all feasible \((N_{\text{coarse}},K,S_{\text{fine}})\) triples that satisfy the budget equation and record the resulting UQM.

## 5. Pareto Front Construction  
- For each model family (GPT‑2‑based vs. LLaMA‑based) plot **UQM (y‑axis)** against **total FLOPs per token (x‑axis)** for every feasible \((N_{\text{coarse}},S_{\text{coarse}},K,S_{\text{fine}})\) condition.  
- Derive the **empirical Pareto frontier** by retaining points where no other point has both **higher or equal quality** and **lower or equal compute**.  
- Compute the **area under the Pareto curve (AUPC)** as a scalar summary of efficiency; higher AUPC indicates a more favorable quality‑compute trade‑off.  
- Additionally, generate **slice‑wise frontiers**:  
  * Vary \(B\) at fixed \((N_{\text{coarse}},K)\) to see the effect of total compute.  
  * Vary \(K\) at fixed \((N_{\text{coarse}},B)\) to isolate the refinement‑set size contribution.  
  * Vary \(S_{\text{fine}}\) at fixed \((N_{\text{coarse}},K,B)\) to isolate the extra denoising‑step contribution.  

## 6. Trade‑off Analysis  
- **Marginal quality gain per additional coarse candidate**: regress UQM against \(\log_2(N_{\text{coarse}})\) (holding \(S_{\text{coarse}},K,S_{\text{fine}},B\) constant).  
- **Marginal quality gain per extra refinement step**: regress UQM against \(S_{\text{fine}}\) (holding \(N_{\text{coarse}},S_{\text{coarse}},K,B\) constant).  
- **Effect of hybrid allocation vs. extremes**: for a set of fixed compute budgets (e.g., 0.5×, 1×, 2× the FLOPs of the base AR model), compare the UQM achieved by:  
  1. **Uniform denoising + static reranking** (each of \(N\) candidates receives exactly \(S = B/(N\cdot F_{\text{diff}})\) steps, then AR‑rerank).  
  2. **Pure candidate exploration** (fix \(S=S_{\text{coarse}}+S_{\text{fine}}\), vary \(N\) such that total FLOPs ≈ \(B\)).  
  3. **CFAR** (coarse‑to‑fine allocation as described).  
  Use **paired bootstrap** (10 000 resamples of prompts) to obtain confidence intervals for the UQM differences.  
- **Statistical significance**: declare a strategy superior if the 95 % bootstrap CI of the UQM difference does **not** contain zero.  
- **Ablation of the AR scorer**: repeat the entire pipeline with random candidate selection (i.e., ignore AR scores for both coarse ranking and refinement selection) to confirm that the observed gains stem from the AR‑guided allocation rather than merely from the two‑stage schedule.  

## 7. Generalizability Checks  
- **Hold‑out evaluation** on HumanEval‑plus and MBPP to ensure observations are not benchmark‑specific.  
- **Unseen DLM**: test a 3B‑parameter diffusion model from the dLLM zoo (not used in the main analysis) to verify that trends extrapolate across architectures.  
- **Alternative lightweight scorers**: replace the AR base model with (i) a distilled 60M‑parameter Transformer, (ii) a frozen BERT‑style MLM, and (iii) a small reward model fine‑tuned on human preferences; run CFAR with each scorer to assess scorer‑agnosticism.  
- **Varying sequence length**: repeat a subset of experiments with \(L=256\) tokens to test scalability of the coarse‑to‑fine schedule.  
- **Per‑benchmark reporting**: alongside UQM, present per‑benchmark normalized scores to confirm that gains are not confined to a single task type.

### Why CFAR is substantively different  
- **Unlike Method 1 (static candidate generation + rerank)**, CFAR does not fix the denoising‑step budget per candidate; instead, it spends a *small* uniform amount on many candidates to explore diversity, then concentrates additional steps on a *selected* subset.  
- **Unlike Method 2 (gradient‑based guidance)**, CFAR never modifies the diffusion latent with a gradient from the AR model; the AR scorer is used only for ranking and selection, preserving the original diffusion dynamics.  
- **Unlike Method 3 (AGADES adaptive early stopping)**, CFAR does not make a per‑step continue/stop decision based on noisy marginal NLL improvements. Instead, it uses a *two‑phase* schedule where the decision to allocate more compute is made *once* after scoring a cheap coarse pool, drastically reducing AR‑scoring overhead and eliminating the need for per‑step greedy policies.  

By explicitly quantifying how much compute should be devoted to candidate exploration versus candidate refinement, CFAR offers a clean, interpretable lever for closing the accuracy headroom (L6) while providing a compute‑normalized efficiency measurement that directly addresses the compute‑normalization gap (L9).
