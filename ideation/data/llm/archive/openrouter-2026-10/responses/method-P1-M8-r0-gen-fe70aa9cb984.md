**Method: AR‑Guided Beam Search Diffusion (ABSD)**  

**Rationale**  
The released diffusion language models (DLMs) generate a full sequence by iteratively denoising a random noise tensor.  Current inference‑time strategies either (i) produce many independent denoising trajectories and rerank them with a lightweight autoregressive (AR) scorer, or (ii) inject AR guidance into the denoising dynamics (e.g., gradient‑based guidance, token‑wise early exit).  Both approaches treat the denoising‑step budget **S** and the number of generation candidates **N** as orthogonal levers: more steps improve the quality of each trajectory, while more candidates increase the chance of sampling a high‑quality output.  

ABSD proposes a *third* lever: **beam width B**, i.e., the number of parallel partial hypotheses that are jointly refined during denoising.  At each diffusion step the AR scorer evaluates the *prefix* of each beam, allowing the search to prune low‑promising hypotheses early and to devote compute to the most promising ones.  Consequently, compute can be re‑allocated dynamically between (a) exploring a diverse set of hypotheses (large B) and (b) refining each hypothesis (large S).  By sweeping B and S we obtain a family of (B,S) operating points that can be compared directly to the conventional (N,S) grid used in the baseline.  Because the AR scorer is used **throughout** the denoising process—not only as a post‑hoc reranker—ABSD tests whether *continuous* lightweight AR guidance yields a superior Pareto frontier of quality versus compute, thereby addressing the accuracy headroom (L6) and the compute‑normalization gap (L9) identified in the target paper.  

The method remains strictly inference‑only, uses only publicly released checkpoints, and adds negligible overhead (a forward pass of the frozen AR model per beam per step).  It can be implemented within the ten‑week timeline on a single RTX 6000 Pro Blackwell by limiting sequence length to 128 tokens and parallelizing beam evaluations across the three team members with GPU access.

### Method Details  

| Step | Description |
|------|-------------|
| **1. Model & Checkpoint Preparation** | • Assemble the five released DLMs (DiffuGPT‑S/M, DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B) and their matching AR base models (GPT‑2‑small/medium, LLaMA‑7B).<br>• Ensure tokenizer compatibility; if a diffusion checkpoint uses a different tokenizer, replace it with the AR base’s tokenizer (no weight change).<br>• Load each diffusion‑AR pair in FP16 on the RTX 6000 Pro Blackwell; keep only one pair resident at a time to stay within the 96 GB memory budget. |
| **2. Unified Quality Metric (UQM)** | • For each benchmark (HumanEval pass@1, pass@10; GSM8K; SIQA; WinoGrande) compute the raw score per model‑condition.<br>• Apply min‑max normalization **within each benchmark** across all conditions so the worst score maps to 0 and the best to 1.<br>• UQM = average of the five normalized scores (range [0, 1]), giving each benchmark equal weight. |
| **3. Compute‑Normalized Efficiency Measurement** | • Diffusion FLOPs per denoising step:  \(F_{\text{diff}} = \alpha \times |\theta| \times L\)  (α≈2 for multiply‑add, \(|\theta|\) = diffusion parameter count, L=128).<br>• AR scorer FLOPs per beam per step: a single forward pass of the frozen AR model over the same sequence length (≈ 1 % of \(F_{\text{diff}}\)).<br>• Total FLOPs for a condition with beam width B and denoising steps S:  <br> \(\text{FLOPs}_{\text{total}} = S \times \bigl[ B \times F_{\text{diff}} + B \times F_{\text{AR}} \bigr] \)  <br> (the AR scorer is called once per beam per step).<br>• Wall‑clock validation: warm‑up 100 tokens, then measure average latency per generated token (including all beam evaluations) using CUDA events; verify linearity between measured latency and FLOP estimate (R² > 0.95).<br>• Report efficiency as **UQM per FLOP** (or UQM per millisecond). |
| **4. AR‑Guided Beam Search Diffusion (ABSD) Procedure** | For each prompt: <br>1. **Initialization** – Sample B independent noise tensors \(\{\mathbf{z}_T^{(b)}\}_{b=1}^{B}\) from the standard diffusion schedule (shape \(L \times d\)).<br>2. **Iterate denoising steps** \(t = T, T-1, \dots, 1\): <br> a. For each beam b, run the diffusion denoising network on \(\mathbf{z}_t^{(b)}\) to obtain predicted clean‑token logits \(\mathbf{p}_\theta(\mathbf{z}_t^{(b)})\).<br> b. Convert logits to a probability distribution and compute the *expected* token embedding \(\hat{\mathbf{e}}_t^{(b)} = \sum_v p_\theta(v|\mathbf{z}_t^{(b)})\mathbf{e}_v\) (or sample a token if preferred).<br> c. **AR guidance query** – feed the partially denoised prefix up to position t (i.e., \(\hat{\mathbf{e}}_{<t}^{(b)}\) with a padding token for the current position) to the frozen AR base model and obtain the conditional log‑likelihood \(\log p_{\text{AR}}(\hat{x}_t^{(b)}|\hat{x}_{<t}^{(b)})\).<br> d. **Beam scoring** – compute a cumulative score for each beam, e.g., the sum of conditional log‑likelihoods up to step t (or the average).<br> e. **Pruning** – keep the top B beams according to this score; discard the rest. <br> f. **Latent update** – apply the diffusion reverse‑process update (as defined by the scheduler) to the surviving beams to obtain \(\mathbf{z}_{t-1}^{(b)}\).<br>3. **Termination** – after step t=0, decode each beam’s latent \(\mathbf{z}_0^{(b)}\) to a token sequence \(\mathbf{x}^{(b)}\) (argmax or sampling).<br>4. **Final reranking** – score each full sequence with the AR model (average token log‑likelihood) and retain the highest‑scoring beam as the model output for that prompt. |
| **5. Swept Hyper‑parameters** | • Beam width \(B \in \{1,2,4,8\}\) (B=1 reduces to standard diffusion with AR‑guided scoring at each step).<br>• Denoising‑step budget \(S \in \{8,16,32,64,128\}\) (by truncating the schedule after S steps).<br>• (Optional) Number of independent ABSD runs \(N_{\text{run}} \in \{1,2,4\}\) to further increase candidate diversity; total compute scales linearly with \(N_{\text{run}}\). |
| **6. Pareto Front Construction** | • For each model family (GPT‑2‑based vs. LLaMA‑based) plot UQM (y‑axis) against total FLOPs per token (x‑axis) for every (B, S, \(N_{\text{run}}\)) condition.<br>• Derive the empirical Pareto frontier by retaining points where no other point has both ≥ quality and ≤ compute.<br>• Compute the **area under the Pareto curve (AUPC)** as a scalar summary of efficiency; higher AUPC indicates a more favorable quality‑compute trade‑off.<br>• Additionally generate slice‑wise frontiers: (i) varying B at fixed S to see the effect of beam width, (ii) varying S at fixed B to isolate denoising‑step contribution, (iii) varying \(N_{\text{run}}\) at fixed (B,S) to assess the impact of independent runs. |
| **7. Trade‑off Analysis** | • **Marginal quality gain per denoising step**: regress UQM versus S (holding B, \(N_{\text{run}}\) constant) and report ΔUQM/ΔS.<br>• **Marginal quality gain per beam width**: regress UQM versus log₂(B) (holding S, \(N_{\text{run}}\) constant).<br>• **Marginal quality gain per additional independent run**: regress UQM versus log₂(\(N_{\text{run}}\)) (holding B, S constant).<br>• **Effect of beam search vs. plain candidate generation**: for a fixed compute budget (e.g., 1×, 2×, 4× the FLOPs of the base AR model), compare UQM achieved by (a) ABSD with varying B, (b) baseline (N,S) grid with AR reranking only after full denoising, and (c) uniform‑step diffusion with increased S only. Use paired bootstrap (10 000 resamples of prompts) to obtain confidence intervals for the UQM differences.<br>• **Statistical significance**: declare a strategy superior if the 95 % bootstrap CI of the UQM difference does not contain zero. |
| **8. Generalizability Checks** | • Hold‑out evaluation on HumanEval‑plus and MBPP to ensure observations are not benchmark‑specific.<br>• Test an additional, unseen diffusion model (e.g., a 3B‑parameter model from the dLLM zoo) to verify that trends extrapolate across architectures.<br>• Alternative lightweight scorers: replace the AR base model with a distilled 60M‑parameter Transformer or a frozen BERT‑style MLM and repeat the ABSD experiment to assess scorer‑agnosticism. |
| **9. Resource‑aware Implementation Plan (10‑week timeline)** | **Weeks 1‑2**: environment setup, checkpoint download, tokenizer alignment, implement beam‑search loop (forward pass of diffusion model + AR scorer per beam per step).<br>**Weeks 3‑4**: run static sweeps over (B, S, \(N_{\text{run}}\)); collect UQM and FLOP data.<br>**Week 5**: Pareto front extraction, AUPC calculation, marginal‑gain regressions.<br>**Week 6**: bootstrap significance testing and baseline (standard N,S reranking) comparison.<br>**Weeks 7‑8**: generalization experiments (held‑out prompts, extra DLM, alternative scorers).<br>**Weeks 9‑10**: write‑up, visualizations (Pareto plots, marginal‑gain bar charts, beam‑width sensitivity curves), prepare reproducibility package (Dockerfile, scripts, seeded RNG). |

### Why ABSD is Substantially Different  

| Prior Proposed Mechanism | Core Idea | ABSD Distinction |
|--------------------------|----------|------------------|
| Static (N,S) grid + post‑hoc AR reranking | Generate many full trajectories, then score once. | ABSD scores **prefixes** at **every denoising step** and prunes beams **online**, coupling exploration (beam width) and refinement (steps) throughout the process. |
| Guidance‑driven diffusion (gradient λ) | Adds AR gradient to the denoising update at each step. | ABSD uses the AR model **only for scoring and ranking**, never modifies the denoising gradient; it is a **search** method rather than a gradient‑based guidance method. |
| AR‑Guided Early Acceptance (ACE) / Selective Denoising (AGSD) | Makes early accept/reject decisions or masks uncertain tokens based on AR scores. | ABSD maintains **multiple parallel hypotheses** (a beam) and decides which to keep based on cumulative AR scores, a strategy akin to beam search in sequence generation but applied to the diffusion denoising timeline. |
| AR‑Guided Importance Resampling (AGIR‑DLM) | Re‑weights samples according to AR scores after generation. | ABSD performs **online selection** during denoising, avoiding the need to generate and store low‑quality full trajectories that are later discarded. |
| Successive‑Halving Allocation (SHADLM) | Tournament‑style elimination of low‑scoring candidates across rounds. | ABSD’s beam pruning is **deterministic and step‑wise**, not based on discrete tournament rounds; it allows a finer granularity of compute allocation (any B and S). |
| Tokenwise Adaptive Denoising with AR‑Guided Early Exit (TADA) | Stops denoising per‑token when AR confidence is high. | ABSD makes **sequence‑level** decisions (beam pruning) while still allowing each token to receive the full denoising budget if its beam survives; it does not rely on per‑token early exit. |

By treating the denoising process as a search problem guided by a lightweight AR scorer, ABSD offers a novel angle on the quality–compute trade‑off that has not been explored in the previously proposed methods. It directly tests whether *continuous* AR‑guided beam search can shift the Pareto frontier upward more effectively than simply increasing denoising steps or the number of independent candidates, thereby answering the research question in a rigorous, compute‑normalized fashion.
