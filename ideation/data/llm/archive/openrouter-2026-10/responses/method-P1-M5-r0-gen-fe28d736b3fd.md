**Method: Layerwise Representation‑Gated AR Scoring (LRGAS)**  

**Rationale**  
The core hypothesis is that a diffusion language model (DLM) that retains more of the autoregressive (AR) model’s representational geometry can exploit a lightweight AR scorer more effectively. Existing proposals either (i) compute a *global* preservation score and then correlate it with the gain from a vanilla AR‑likelihood reranker, or (ii) rank candidates solely by a representation‑similarity metric.  
LRGAS takes a different, finer‑grained approach: it uses *layer‑wise* measures of AR‑DLM representational alignment to *gate* the contributions of the AR scorer at each transformer layer. Intuitively, if a particular layer’s hidden space is well‑aligned with the AR backbone, the AR scorer’s logits (or hidden‑state‑based scores) coming from that layer are more reliable; if the alignment is poor, those logits should be down‑weighted. By making the reranking score a weighted sum of layer‑wise AR scores, where the weights are derived directly from the measured preservation, we obtain a scorer whose effectiveness is expected to scale monotonically with the degree of representation preservation. This lets us test the research question in a way that is mechanistically distinct from prior work while staying strictly inference‑only and fully compatible with the resource constraints.

### Step‑by‑step Procedure  

| Step | Goal | Concrete Actions (inference‑only) | Resources & Constraints |
|------|------|-----------------------------------|--------------------------|
| **0. Preparation** | Build a reproducible pipeline that fits the 1× RTX 6000 Pro Blackwell (96 GB) and 10‑week schedule. | • Download the released DLM checkpoints (DiffuGPT‑S/M, DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B) and their AR base models (GPT‑2‑small/medium for GPT‑2‑based DLMs; LLaMA‑7B for LLaMA‑based DLMs). <br>• Tokenize a held‑out probing corpus (≈10 k sentences from WikiText‑103 + C4) with each model’s tokenizer; store token IDs. <br>• Assemble the benchmark suite (HumanEval, GSM8K, SIQA, WinoGrande) and a normalisation script (min‑max to \([0,1]\)). <br>• Enable activation‑checkpointing and 8‑bit quantisation (`bitsandbytes`) for the 6.74B DiffuLLaMA so it fits in GPU memory with batch‑size ≥ 4. <br>• Split work among the three GPU‑enabled team members (each owns a subset of models/step‑budgets) and write results to a shared CSV/Parquet store. | One RTX 6000 Pro Blackwell, 8‑bit quantisation + activation checkpointing, CPU‑only work for data prep/eval harnesses. |
| **1. Compute Layerwise Representation Preservation** | Obtain a per‑layer similarity score \(s_\ell\in[0,1]\) that quantifies how much the DLM’s hidden‑state subspace at layer \(\ell\) matches that of its AR backbone. | **1.1 Forward pass on probing corpus** – For every sentence in the probing corpus, run the DLM *inference‑only* (no grad) and collect the post‑attention hidden‑state tensor \(\mathbf{H}^{\text{DLM}}_\ell\in\mathbb{R}^{N\times D}\) for each transformer layer \(\ell\). Do the same with the frozen AR base model (same tokenizer, same sequence length) to obtain \(\mathbf{H}^{\text{AR}}_\ell\). <br>**1.2 Similarity metric** – Compute **Centered Kernel Alignment (CKA)** with a linear kernel between \(\mathbf{H}^{\text{DLM}}_\ell\) and \(\mathbf{H}^{\text{AR}}_\ell\): <br>\[
\text{CKA}_\ell = \frac{\text{tr}(\mathbf{K}^{\text{DLM}}_\ell \mathbf{K}^{\text{AR}}_\ell)}{\|\mathbf{K}^{\text{DLM}}_\ell\|_F \,\|\mathbf{K}^{\text{AR}}_\ell\|_F},
\quad \mathbf{K}^{\text{DLM}}_\ell = \mathbf{H}^{\text{DLM}}_\ell (\mathbf{H}^{\text{DLM}}_\ell)^\top,
\] <br>where \(N\) is the total number of tokens in the probing corpus. CKA is already bounded in \([0,1]\); set \(s_\ell = \text{CKA}_\ell\). <br>**1.3 Optional depth weighting** – Store also a depth weight \(w_\ell = \exp(-\lambda \cdot (\ell/L))\) (with \(\lambda\) chosen so that deeper layers receive higher weight; e.g., \(\lambda=1\)). These weights will be used later when aggregating layer‑wise scores. | No gradient updates; only forward passes and a cheap linear‑algebra operation (matrix multiplication) on CPU or GPU. The probing corpus is small enough to fit in memory. |
| **2. Multi‑Candidate Generation** | Produce a diverse set of outputs for each prompt at several denoising‑step budgets. | • Choose a prompt set covering the three benchmark families (e.g., 200 HumanEval prompts, 200 GSM8K questions, 200 SIQA/WinoGrande items). <br>• For each DLM \(i\) and each denoising‑step budget \(S\in\{16,32,64,128\}\): <br> - Sample **K = 8** candidates per prompt using nucleus sampling (top‑p = 0.9). <br> - Store the raw token strings. <br>• Use a fixed random seed across models to make candidate sets comparable. | Pure inference; batch size limited by GPU memory (≈ 4‑8 sequences per step). |
| **3. Layerwise‑Gated AR Scoring** | Compute a reranking score that modulates the AR scorer’s output by the per‑layer preservation measured in Step 1. | **3.1 AR scorer forward pass (teacher‑forcing)** – For each generated candidate string, feed it through the frozen AR base model (teacher‑forcing: the model sees the candidate and predicts the next token at each position). Collect the post‑attention hidden states \(\mathbf{H}^{\text{AR}}_\ell\) (or directly the logits) for every layer \(\ell\). <br>**3.2 Layer‑wise AR score** – For each layer \(\ell\), reduce the hidden‑state (or logit) tensor to a scalar that reflects the candidate’s likelihood under the AR model. A simple, training‑free choice is the **average log‑probability** of the token at each position: <br>\[
a_{\ell}^{\text{cand}} = \frac{1}{T}\sum_{t=1}^{T} \log p_{\text{AR}}(x_t \mid x_{<t}),
\] <br>where \(T\) is the candidate length. This can be obtained from the AR model’s logits without extra parameters. <br>**3.3 Gating by preservation** – Multiply each layer‑wise AR score by the preservation similarity from Step 1: <br>\[
g_{\ell}^{\text{cand}} = s_\ell \times a_{\ell}^{\text{cand}}.
\] <br>If depth weighting is desired, use \(w_\ell\) as well: \(g_{\ell}^{\text{cand}} = w_\ell \, s_\ell \, a_{\ell}^{\text{cand}}\). <br>**3.4 Aggregate to a final candidate score** – Sum across layers: <br>\[
\text{Score}^{\text{LRGAS}}_{\text{cand}} = \sum_{\ell=1}^{L} g_{\ell}^{\text{cand}}.
\] <br>**3.5 Ranking** – Sort the K candidates in descending order of \(\text{Score}^{\text{LRGAS}}\); the top‑1 after this sort is the *LRGAS‑reranked* output. <br>**3.6 Cost measurement** – Record the wall‑clock time for one AR forward pass per candidate (≈ 0.5 ms for GPT‑2‑small, ≈ 2 ms for 8‑bit LLaMA‑7B). The total reranking cost per prompt is \(K \times t_{\text{AR}}\). | Only forward passes through the frozen AR model (no training). The gating operation is a simple element‑wise multiplication and addition. |
| **4. Baseline AR‑Only Reranking (for comparison)** | Provide a vanilla likelihood‑based reranker to isolate the effect of gating. | Repeat Step 3 but **omit the preservation gate** (i.e., set \(s_\ell = 1\) for all \(\ell\)). The resulting score is simply the sum of layer‑wise AR log‑likelihoods. This yields a baseline reranked output and its associated gain. | Same cost as LRGAS (the AR forward pass is already computed). |
| **5. Quality Measurement** | Map raw outputs to a unified, comparable metric. | • For each benchmark compute: <br> - HumanEval: pass@k for k = 1,10. <br> - GSM8K: exact‑match accuracy. <br> - SIQA & WinoGrande: accuracy (multiple‑choice). <br>• Normalise each raw score to \([0,1]\) across **all** model‑step‑budget‑reranking conditions (min‑max scaling). <br>• Define the **Unified Quality Score (UQS)** as the arithmetic mean of the four normalised components (HumanEval@1, HumanEval@10, GSM8K, (SIQA+WinoGrande)/2). <br>• Also compute the *oracle* UQS (best candidate among the K generated) to quantify the accuracy headroom for each condition. | All metrics computed offline on CPU; no extra GPU load. |
| **6. Experimental Contrasts** | Isolate the two sources of improvement: (a) representation‑gated reranking vs. (b) more denoising steps. | For each DLM \(i\) and low step budget \(S_{\text{low}}=16\): <br> - **LRGAS reranking gain**: \(\Delta^{\text{rank,LRGAS}}_{i,S_{\text{low}}} = \text{UQS}_{i,S_{\text{low}}}^{\text{LRGAS}} - \text{UQS}_{i,S_{\text{low}}}^{\text{top‑1}}\). <br> - **Baseline AR reranking gain**: \(\Delta^{\text{rank,base}}_{i,S_{\text{low}}} = \text{UQS}_{i,S_{\text{low}}}^{\text{base}} - \text{UQS}_{i,S_{\text{low}}}^{\text{top‑1}}\). <br> - **Denoising‑step gain** (no reranking): \(\Delta^{\text{step}}_{i} = \text{UQS}_{i,128}^{\text{top‑1}} - \text{UQS}_{i,16}^{\text{top‑1}}\). <br>• Compute the *relative efficiency* of LRGAS vs. baseline: <br>\[
\eta^{\text{LRGAS}}_i = \frac{\Delta^{\text{rank,LRGAS}}_{i,S_{\text{low}}}}{\Delta^{\text{step}}_{i}},\qquad
\eta^{\text{base}}_i = \frac{\Delta^{\text{rank,base}}_{i,S_{\text{low}}}}{\Delta^{\text{step}}_{i}}.
\] <br>Values > 1 indicate that the respective reranking strategy yields more quality per unit of added compute than adding denoising steps from 16→128. | Requires only the four step budgets; no additional model runs. |
| **7. Statistical Modelling** | Test whether layer‑wise preservation predicts the *extra* benefit of gating over the baseline AR scorer, and whether this differs by architecture or step budget. | Fit a **linear mixed‑effects model** (LME) with the *incremental gain* from gating as the dependent variable: <br>\[
\delta^{\text{rank}}_{ijk\ell}= \beta_0 + \beta_1 \overline{s}_i + \beta_2 S_j + \beta_3 R_{k} + \beta_4 (\overline{s}_i \times S_j) + \beta_5 (\overline{s}_i \times R_{k}) + \beta_6 (S_j \times R_{k}) + \beta_7 A_i + \beta_8 (\overline{s}_i \times A_i) + u_i + \epsilon_{ijk\ell},
\] <br>where: <br>• \(\overline{s}_i = \sum_{\ell} w_\ell s_\ell\) is the depth‑weighted average preservation for model \(i\). <br>• \(S_j\) = denoising‑step budget (log‑scaled). <br>• \(R_k\) = reranking indicator (0 = top‑1, 1 = LRGAS‑reranked). <br>• \(A_i\) = architecture dummy (0 = GPT‑2‑based, 1 = LLaMA‑based). <br>• \(u_i\sim\mathcal{N}(0,\sigma^2_{\text{model}})\) captures model‑specific random intercepts. <br>Key hypotheses: <br> - **H1**: \(\beta_5 > 0\) (the incremental gain from gating grows with preservation). <br> - **H2**: \(\beta_8 \neq 0\) (the preservation‑gain relationship differs between GPT‑2‑ and LLaMA‑based DLMs). <br> - **H3**: \(\beta_4 > 0\) (the benefit of extra steps is larger when preservation is high). <br>Additionally, compute Spearman’s \(\rho\) between \(\overline{s}_i\) and the relative efficiency \(\eta^{\text{LRGAS}}_i\) to directly address the core research question. | All modelling performed on CPU (e.g., `statsmodels` or `lme4` via R). |
| **8. Efficiency Accounting** | Translate quality gains into comparable compute cost. | • Measure wall‑clock time for a single denoising step (averaged over 100 runs) for each DLM (with activation checkpointing & 8‑bit quant). <br>• Compute **cost per step**: \(C^{\text{step}}_i = t^{\text{step}}_i\). <br>• Compute **cost of LRGAS reranking**: \(C^{\text{rank}}_i = K \times t^{\text{AR}}_i\) (AR forward pass per candidate). <br>• Define **efficiency ratio**: <br>\[
\epsilon_i = \frac{\Delta^{\text{rank,LRGAS}}_{i,S_{\text{low}}} / C^{\text{rank}}_i}{\Delta^{\text{step}}_{i} / (C^{\text{step}}_i \times (128-16))}.
\] <br>Values > 1 indicate LRGAS gives more quality per FLOP/second than adding denoising steps. | Timing measurements are cheap (< 5 min total). |
| **9. Ablation & Robustness Checks** | Verify that findings are not artefacts of specific choices. | • Vary the similarity metric (replace CKA with **Procrustes similarity** or **SVCCA**) in Step 1 and repeat the pipeline. <br>• Change the nucleus sampling p (0.8, 0.95) and K (4, 16). <br>• Replace the AR scorer’s layer‑wise log‑likelihood with the **average hidden‑state norm** or **cosine similarity to a class prototype** to ensure the effect is not tied to a particular scoring function. <br>• Run a *control* where the preservation gate \(s_\ell\) is replaced by a random vector drawn from Uniform[0,1] (same distribution) to confirm that gains are not due to chance weighting. <br>• Test alternative AR scorers (DistilGPT‑2, MiniLM) to confirm the < 1 % FLOP claim. | All ablations reuse the same generated candidate pool; no extra generation needed. |
| **10. Reporting & Reproducibility** | Ensure transparent dissemination. | • Archive all scripts, random seeds, and environment specifications (Dockerfile or Conda yaml). <br>• Publish the extracted per‑layer preservation scores \(\{s_\ell\}\) and the final results table on an open repository (e.g., HuggingFace datasets + Zenodo). <br>• Provide a short “re‑run” notebook that reproduces the key figures (preservation vs. LRGAS gain, efficiency ratio). | Fits the ten‑week timeline: weeks 1‑2 for setup, weeks 3‑5 for generation & scoring, week 6 for metric computation, weeks 7‑8 for statistical analysis, weeks 9‑10 for write‑up and reproducibility packaging. |

### How LRGAS Answers the Research Question  

1. **Quantifying preservation** – Step 1 yields a *layer‑wise* similarity profile \(\{s_\ell\}\) that directly measures how much each transformer layer of the DLM mirrors the AR backbone.  
2. **Linking preservation to reranking power** – Step 3 builds a scorer whose contribution from each layer is *proportional* to \(s_\ell\). If a model preserves AR representations well (high \(s_\ell\)), the AR scorer’s logits at those layers are trusted more; if preservation is low, those logits are down‑weighted. Thus the *expected* reranking gain is a monotonic function of the preservation profile.  
3. **Empirical test** – By comparing the gain from the gated scorer (LRGAS) to the gain from a vanilla AR‑likelihood scorer (baseline) and to the gain from adding denoising steps, we can directly assess:  
   * Whether higher preservation leads to a *larger* incremental benefit from gating (H1).  
   * Whether this relationship differs between GPT‑2‑based and LLaMA‑based DLMs (H2).  
   * Whether the benefit of extra denoising steps interacts with preservation (H3).  
4. **Efficiency comparison** – The relative efficiency ratios (\(\eta\) and \(\epsilon\)) tell us whether the lightweight, preservation‑guided reranking recovers more accuracy headroom per unit of compute than simply increasing the denoising‑step budget.  

Because the method never modifies model parameters, relies only on released checkpoints, and uses a single GPU with 8‑bit quantisation and activation checkpointing, it satisfies all feasibility constraints while offering a novel, mechanistic angle on the interplay between representation preservation and inference‑time selection.
