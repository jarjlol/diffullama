**Method:**  
| Step | Goal | Concrete actions | Resources & Constraints |
|------|------|------------------|--------------------------|
| **0. Preparation** | Build an inference‑only, reproducible pipeline that respects hardware, timeline and the “no‑training” rule. | • Download the released checkpoints: DiffuGPT‑S/M, DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B and the matching AR base models (GPT‑2‑small/medium, LLaMA‑7B). <br>• Tokenise a **held‑out probing corpus** (see Step 1) **once** with each model’s tokenizer and store the token IDs. <br>• Assemble the downstream benchmark suite (HumanEval, GSM8K, SIQA, WinoGrande) and write an evaluation harness that (i) extracts answers, (ii) computes raw scores, and (iii) normalises each benchmark to \([0,1]\) **using a fixed reference set** (the first 10 % of prompts from each benchmark, stored before any experimentation). <br>• For the largest model (DiffuLLaMA‑6.74B) enable activation‑checkpointing and 8‑bit quantisation (`bitsandbytes`) so that a batch of ≥4 sequences fits in the 96 GB GPU. <br>• Parallelise work across the three GPU‑enabled team members: each member owns a disjoint subset of (model, step‑budget) pairs and writes results to a shared Parquet/CSV store. <br>• Fix all random seeds (numpy, torch, CUDA) and log them; store the environment (conda yaml + Dockerfile). | One RTX 6000 Pro Blackwell (96 GB), 8‑bit quantisation, activation checkpointing, CPU‑only work for data‑prep/eval harnesses. |
| **1. Quantify AR‑representation preservation** | Obtain a scalar “preservation score” \(P_i\) for each DLM that reflects similarity of its hidden‑state geometry to that of its AR backbone. | **1.1 Probing corpus** – Sample 10 000 sentences from WikiText‑103 + C4 combined. Use spaCy (en_core_web_sm) to segment documents into sentences; discard sentences >128 tokens after tokenisation with the AR tokenizer to keep sequence length uniform. <br>**1.2 Feature extraction (inference‑only)** – For every sentence, run the DLM **forward** with no gradients. Register a forward‑hook on each Transformer block **after the attention sub‑layer and before the feed‑forward network** (the residual stream). Record the hidden‑state tensor of shape \([N, D]\) where \(N\) = token length, \(D\) = hidden size. Do the same with the frozen AR base model (same token IDs, same length). <br>**1.3 Similarity per layer** – Compute **Centered Kernel Alignment (CKA)** with a linear kernel between the DLM and AR hidden‑state matrices (\(N\times D\)). Also compute **linear probing**: fit a ridge‑regression model (no gradient to the DLM) to predict AR hidden states from DLM hidden states; record the coefficient of determination \(R^2\). Solve ridge regression analytically on CPU (scikit‑learn). <br>**1.4 Layer weighting** – Assign weight \(w_\ell = \exp\bigl(-\lambda \cdot \frac{L-\ell}{L}\bigr)\) to layer \(\ell\) (where \(L\) = total number of layers, \(\ell=1\) is the first layer). Primary analysis uses \(\lambda=0.5\); test \(\lambda\in\{0.2,0.5,0.8\}\) in ablation. <br>**1.5 Aggregation** – Compute the weighted average of CKA across layers: \(P_i^{\text{CKA}} = \sum_{\ell} w_\ell \,\text{CKA}_\ell / \sum_\ell w_\ell\). Do the same for \(R^2\) to obtain \(P_i^{\text{probe}}\). The primary preservation score is \(P_i = P_i^{\text{CKA}}\); the probing score is retained as a secondary, complementary measure. | No training; only forward passes. Ridge regression solved analytically on CPU (scikit‑learn). |
| **2. Multi‑candidate generation** | Produce a diverse set of outputs for each prompt at several denoising‑step budgets. | • Build a prompt set that mirrors the three benchmark families: 200 HumanEval prompts, 200 GSM8K questions, 200 SIQA/WinoGrande items (total 600 prompts). <br>• For each DLM and each denoising‑step budget \(S \in \{16,32,64,128\}\): <br> - Sample **K = 8** candidates per prompt using nucleus sampling with \(p=0.9\). <br> - **Noise seed handling:** For each prompt, set a base seed \(s_{prompt}\). Candidate \(c\) uses seed \(s_{prompt}+c\) (ensures independent noise while keeping the overall randomness reproducible across models). <br> - Store the raw token sequences; optionally keep the per‑step denoising trace for later analysis. <br>• Use the same global random seed across all models so that the *prompt* seeds are comparable. | Generation is pure inference; batch size limited by GPU memory (≈ 4‑8 sequences per step). |
| **3. Lightweight, training‑free reranking** | Apply a suitably sized AR scorer to reorder candidates and compute the selection gain. | • **Primary scorer (architecture‑matched):** <br> - For GPT‑2‑based DLMs (DiffuGPT‑S/M) use **GPT‑2‑small** (124 M). <br> - For LLaMA‑based DLMs (DiffuLLaMA‑6.74B, Dream‑7B, LLaDA‑8B, DiffuCoder‑7B) use **LLaMA‑7B** (or a distilled 1 B version if memory is tight). <br>• **Cross‑family scorer (ablation):** GPT‑2‑small applied to LLaMA‑based DLMs and LLaMA‑7B applied to GPT‑2‑based DLMs (to test scorer‑model family confounding). <br>• For each candidate, compute the **average negative log‑likelihood** (or perplexity) under the scorer; lower score = higher likelihood. <br>• Rank candidates ascending by this score; the top‑1 after reranking is the *selected* output. <br>• Measure the scorer’s FLOPs and wall‑clock time (≈ 0.3 % of a single denoising step for the largest DLM; < 1 ms per candidate). | Scorers fit easily in memory; latency contribution negligible (< 1 ms per candidate). |
| **4. Quality measurement** | Translate raw outputs into a unified, comparable metric while preserving benchmark‑specific information. | • Compute raw scores per benchmark: <br> - **HumanEval**: pass@1 and pass@10 (standard unit‑test harness). <br> - **GSM8K**: exact‑match accuracy after answer extraction. <br> - **SIQA & WinoGrande**: multiple‑choice accuracy. <br>• **Normalisation** – For each benchmark separately, apply min‑max scaling **using the fixed reference set** (the first 10 % of prompts) so that the worst observed score in that reference set maps to 0 and the best to 1. This yields comparable \([0,1]\) scores that are independent of the experimental matrix. <br>• **Unified Quality Score (UQS)** – Primary metric: **simple average** of the four normalised benchmark scores (equal weight). <br>• **Secondary metric:** Compute a PCA‑derived weight vector on a held‑out validation split (10 % of prompts) and report the resulting UQS; discuss any divergence. <br>• Also compute the **oracle UQS** (best candidate among the K generated) to quantify the *accuracy headroom* for each condition. | All scoring and normalisation performed offline on CPU; no extra GPU load. |
| **5. Experimental contrasts** | Isolate the two sources of improvement: (a) reranking vs. (b) more denoising steps. | For each DLM \(i\) and low step budget \(S_{\text{low}}=16\): <br> - **Reranking gain**: \(\Delta^{\text{rank}}_{i,S_{\text{low}}} = \text{UQS}_{i,S_{\text{low}}}^{\text{ranked}} - \text{UQS}_{i,S_{\text{low}}}^{\text{top‑1}}\). <br> - **Denoising‑step gain** (no reranking): \(\Delta^{\text{step}}_{i} = \text{UQS}_{i,128}^{\text{top‑1}} - \text{UQS}_{i,16}^{\text{top‑1}}\). <br>• **Gain‑ratio (step‑budget normalised)**: \(\eta_i = \dfrac{\Delta^{\text{rank}}_{i,S_{\text{low}}}}{\Delta^{\text{step}}_{i}}\) (values > 1 indicate reranking yields more quality per added denoising step). <br>• **Compute‑normalised efficiency**: measure wall‑clock time per denoising step \(t^{\text{step}}_i\) (averaged over 100 runs) and scorer time per candidate \(t^{\text{scorer}}_i\). Define <br> \(\epsilon_i = \dfrac{\Delta^{\text{rank}}_{i,S_{\text{low}}} / (K \cdot t^{\text{scorer}}_i)}{\Delta^{\text{step}}_{i} / \bigl(t^{\text{step}}_i \times (128-16)\bigr)}\). <br> Values > 1 mean reranking delivers more quality per unit of compute than adding denoising steps. | Requires only the four step budgets; no additional model runs. Timing measurements are cheap (< 5 min total). |
| **6. Statistical modelling (descriptive focus)** | Test whether preservation predicts reranking advantage and explore architecture/step‑budget moderation, acknowledging the limited number of DLMs (n=5). | • Create a tidy table with one row per (model, step budget, reranking condition, prompt). <br>• **Primary analysis (exploratory):** Compute **Spearman’s \(\rho\)** between the model‑level preservation score \(P_i\) and the reranking gain \(\Delta^{\text{rank}}_{i,16}\) (and separately with \(\eta_i\) and \(\epsilon_i\)). Obtain bias‑corrected bootstrap confidence intervals (10 000 resamples) **resampling at the prompt level** (i.e., recompute model‑level gains from bootstrap samples of prompts) to reflect uncertainty due to finite prompt set. <br>• **Secondary analysis:** Fit a simple linear regression \(\Delta^{\text{rank}}_{i,16} = \beta_0 + \beta_1 P_i + \varepsilon_i\) (no interactions) and report OLS estimates with bootstrap‑derived 95 % CIs (prompt‑level resampling). <br>• **Sensitivity check:** Fit a Bayesian linear regression with weakly informative priors (Normal(0,2.5) for \(\beta\), Half‑Cauchy(0,2.5) for \(\sigma\)) and report posterior means and 95 % credible intervals. <br>• **Architecture effect:** Report the mean preservation score and mean reranking gain for each family (GPT‑2‑based vs. LLaMA‑based) and compute a two‑sample t‑test (bootstrap) **as a descriptive check**, not as formal inference. <br>• **Step‑budget moderation:** Compute the gain‑ratio \(\eta_i\) at each low budget (16, 32, 64) and examine its correlation with \(P_i\) via Spearman (prompt‑level bootstrap). This avoids over‑parameterising a model with interaction terms. | All modelling performed on CPU (statsmodels, pymc3/bootstrapped). |
| **7. Behavioral validation of preservation** | Verify that higher preservation scores correspond to stronger AR‑like behaviour of the DLM, not just geometric similarity. | • For each DLM and each prompt, compute the **average negative log‑likelihood** of the DLM’s *top‑1* candidate under the **architecture‑matched AR scorer** (same as used in Step 3). <br>• Correlate this AR‑likelihood (averaged over prompts) with the preservation score \(P_i\) across the five DLMs (Spearman, prompt‑level bootstrap CI). <br>• A significant positive correlation supports the claim that preservation reflects the extent to which the DLM retains AR‑predictive power. | No extra generation; uses existing top‑1 outputs and scorer likelihoods. |
| **8. Efficiency accounting (non‑linear step gains)** | Translate quality gains into comparable compute cost while respecting the observed diminishing returns of denoising steps. | • Fit a smooth monotonic curve (e.g., a logarithmic or Michaelis‑Menten function) to the relationship **UQS vs. denoising steps** for each DLM using the four measured points (16, 32, 64, 128). <br>• Derive the **marginal quality per added step** from the fitted curve and compute the expected gain from 16→128 steps as the integral of the marginal curve. <br>• Use this *model‑based* denoising gain in place of the raw \(\Delta^{\text{step}}_{i}\) when computing \(\eta_i\) and \(\epsilon_i\). <br>• Report both the **raw** (linear‑step) and **curve‑based** efficiency ratios to show sensitivity to the assumption of linear scaling. | Curve fitting performed on CPU (scipy.optimize). No extra GPU work. |
| **9. Ablation & robustness checks** | Verify that findings are not artefacts of specific choices. | • **Scorer size** – repeat Step 3 with GPT‑2‑medium (355 M) and DistilGPT‑2 (82 M) to confirm the < 1 % FLOP claim and test whether scorer capacity influences the preservation‑gain relationship. <br>• **Alternative preservation metrics** – compute SVCCA, Procrustes similarity, and CKA with an RBF kernel; compare rankings of \(P_i\). <br>• **Hidden‑state extraction point** – in addition to the primary “post‑attention, pre‑FF” we will also extract (i) post‑FF, (ii) average of all layers, and (iii) the CLS‑token representation (if available) to test robustness. <br>• **Candidate diversity** – vary nucleus \(p\) (0.8, 0.9, 0.95) and \(K\) (4, 8, 16); compute pairwise self‑BLEU entropy to quantify diversity and test whether diversity mediates the preservation‑gain link. <br>• **Generation‑domain probing set** – extract 2 k tokens from the actual benchmark prompts (HumanEval + GSM8K) and recompute preservation scores; report correlation with the original WikiText‑based scores. <br>• **Control scorer** – replace the AR scorer with a random scorer (uniform scores) to ensure observed gains are not due to chance ordering. <br>• **Normalization reference** – repeat the analysis using a *different* fixed reference set (e.g., the first 5 % of prompts) for min‑max scaling to confirm robustness to the choice of reference pool. <br>• **Lambda sweep** – test \(\lambda \in \{0.2,0.5,0.8\}\) for the exponential layer weighting in Step 1.3. | All ablations reuse the same generated candidate pool; no extra generation needed. |
| **10. Reporting & reproducibility** | Ensure transparent dissemination and enable replication. | • Archive all scripts, random seeds, and environment specifications (conda yaml + Dockerfile). <br>• Store the extracted hidden‑state features (optional) and the final results table on an open repository (HF datasets + Zenodo). <br>• Provide a short “re‑run” notebook that reproduces the key figures: preservation vs. reranking gain, efficiency ratios (raw & curve‑based), and the bootstrap‑derived coefficient/plots. <br>• Include a **pre‑registration** document (OSF) outlining the primary hypotheses, analysis plan, and correction for multiple tests (we report family‑wise error‑controlled p‑values via the bootstrap max‑t method). | Fits the ten‑week timeline: weeks 1‑2 for setup, weeks 3‑5 for generation & scoring, week 6 for metric computation & normalisation, week 7‑8 for statistical analysis & efficiency accounting, weeks 9‑10 for ablation, write‑up, and reproducibility packaging. |

### Rationale for the Revised Method  

1. **Scorer‑model family confounding** – The primary scorer is now **architecture‑matched** (GPT‑2‑small for GPT‑2‑based DLMs, LLaMA‑7B for LLaMA‑based DLMs). This eliminates the systematic bias whereby a universal GPT‑2 scorer would artificially inflate preservation‑gain correlations for GPT‑2‑based models. Cross‑family scorer ablations remain to test whether the preservation‑gain relationship holds when the scorer architecture differs from the DLM’s backbone.

2. **Statistical validity with n=5** – All inferential statistics are framed as **descriptive exploratory analyses**. Bootstrap confidence intervals are obtained by **resampling prompts** (the unit that actually varies across observations), which properly captures uncertainty due to finite evaluation sets. We report effect sizes (Spearman \(\rho\), regression coefficients) with CIs and explicitly avoid claiming statistical significance; the Bayesian regression serves as a sensitivity check. This aligns with the feedback that hypothesis testing is under‑powered.

3. **Construct validation of preservation** – A **behavioral check** (Step 7) correlates preservation scores with the AR‑likelihood of the DLM’s own outputs under the matched scorer. If preservation truly reflects retained AR predictive power, higher \(P_i\) should predict higher AR‑likelihood, providing evidence that the geometric similarity measured by CKA is functionally relevant.

4. **Refined quality metric** – We retain the simple average UQS as the primary, interpretable metric (equal weighting of four benchmarks). As a secondary, exploratory metric we compute PCA‑derived weights on a held‑out validation split and report the resulting UQS, allowing readers to assess sensitivity to weighting choices. This addresses concerns about equal‑interval scaling across heterogeneous tasks.

5. **Non‑linear denoising‑step gains** – Instead of assuming each additional denoising step yields equal quality improvement, we fit a smooth monotonic curve to the observed UQS‑vs‑step points and compute the expected gain from 16→128 steps as the integral of the marginal curve. The resulting **curve‑based efficiency ratios** (\(\eta_i^{\text{curve}}, \epsilon_i^{\text{curve}}\)) are reported alongside the raw linear‑step ratios, making the efficiency comparison robust to diminishing returns.

6. **Clarifications for reproducibility** –  
   * Hidden‑state extraction is performed via **forward hooks** on the residual stream after attention and before the feed‑forward network.  
   * For diffusion sampling, each candidate receives an **independent noise seed** derived from a prompt‑level base seed plus candidate index, ensuring diversity while keeping the overall random process reproducible across models.  
   * The probing corpus is constructed by **sentence‑segmenting** WikiText‑103 and C4 with spaCy, then filtering to a uniform max length.  
   * Bootstrap units are explicitly defined (prompt‑level) for all uncertainty estimates.

7. **Feasibility** – All steps respect the inference‑only constraint, the single RTX 6000 Pro Blackwell (96 GB) limit (activation checkpointing + 8‑bit quantisation for the 6.74B model), and the ten‑week timeline. Generation is capped at 128 steps, a range where the target paper shows informative marginal returns. CPU‑heavy tasks (feature extraction, probing, evaluation, statistical modelling, curve fitting) are distributed to the four CPU‑only team members.

8. **Generalisability** – The protocol is model‑agnostic: any DLM released with an associated AR base can be inserted. Preservation metrics (CKA, linear probing, SVCCA, Procrustes) and scorers (GPT‑2‑family, LLaMA‑family, alternatives) are interchangeable. The unified quality metric can be recomputed with alternative benchmarks or weighting schemes, and the efficiency analysis can accommodate any number of denoising steps or scorer sizes.

By tightly integrating representation‑preservation analysis with a rigorous, efficiency‑focused comparison of lightweight selection versus extra denoising (including a behavioral validation and non‑linear step‑gain modeling), this method moves beyond empirical tuning to provide a mechanistic explanation for why some DLMs benefit more from reranking than others. It bridges the representation‑alignment literature (REPR‑ALIGN, PreDiff‑LM) with pure inference‑time trade‑off work (Jacobi Forcing, TESS 2), offering actionable insight for future DLM design and deployment.
